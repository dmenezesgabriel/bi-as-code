# Open-source release — security hardening and npm publishing

**Ephemeral.** Construction scaffolding for Phase 9: making the repository safe to open and publishing `biac` to npm from GitHub Actions. Deleted when Phase 9 closes. Nothing here belongs in a durable document — see [ADR-0001](../adr/0001-record-architecture-decisions.md).

## How it was built

R12, 2026-11-06. Two owner repositories read through `gh api repos/dmenezesgabriel/<repo>/contents/<path>` (`claude-acc-manager` is public, `jupydroid` is private), well-maintained npm projects read the same way, the 4 feature references read in `research_repos/` (every path checked with `test -e`), and npm's own documentation fetched that day.

Owner decisions (2026-11-06): license **Apache-2.0**; package name **`biac`** (`npm view biac` answers 404); `master` protected, work goes feature branch → PR → merge; versioning and publishing driven by conventional commits; choose the safest, most conventional, evidence-grounded option, with no workaround and no over-engineering.

| A trusted-publisher config names user, repository, workflow file name and optional environment; it expires after 2 days without a first publish                           | same                                                                                        |

| Verify with `npm audit signatures`                                                                                                                                        | https://docs.npmjs.com/generating-provenance-statements                                     |
| release-please: `fix` → patch, `feat` → minor, `!` → major; manifest mode; `bump-minor-pre-major`; node strategy                                                          | https://github.com/googleapis/release-please-action, `.../docs/manifest-releaser.md`        |
| `GITHUB_TOKEN` events start no workflow, so a release PR needs an App or personal token to get its required checks                                                        | release-please-action README; `claude-acc-manager:.github/workflows/release-cut.yml` header |

## Decisions the slices must carry out

| Decision                    | Choice                                                                                                                                                                                                                                                                                                                | Evidence                                                                                                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Release tool                | release-please (manifest, `release-type: node`, `include-component-in-tag: false`, `bump-minor-pre-major`) — works with a protected `master`; `npm/cli` uses it with `release-please-config.json` and `.release-please-manifest.json` (the owner's repos use python-semantic-release, configured in `pyproject.toml`) | semantic-release with `@semantic-release/git` would need a ruleset bypass; changesets needs a file per PR |
| Merge method                | squash only; the PR title is the conventional commit, checked by the repo's own `commitlint.config.js`                                                                                                                                                                                                                | `jupydroid:.github/workflows/ci.yml` `commit-messages`                                                    |
| Publish gate                | environment `npm` with a required reviewer; `id-token: write` on the publish job only; one workflow file `release.yml` bound as the trusted publisher                                                                                                                                                                 | vite, vitest, mosaic and both owner repos gate on an environment                                          |
| Scanner installation        | release binaries pinned by version and sha256, no marketplace action that fetches code at run time                                                                                                                                                                                                                    | `jupydroid:.github/workflows/security.yml`                                                                |
| Actions pinning             | full commit SHA with a `# vX.Y.Z` comment, kept fresh by Dependabot with a 7-day cooldown                                                                                                                                                                                                                             | both owner repos; GitHub's hardening guide                                                                |
| Visibility-dependent jobs   | `codeql`, `dependency-review`, `scorecard` guarded by `github.event.repository.visibility == 'public'`                                                                                                                                                                                                                | both owner repos                                                                                          |
| First publish               | manual by the owner (npm requires the package to exist), then `npm trust github … --allow-publish` within 2 days                                                                                                                                                                                                      | https://docs.npmjs.com/cli/v11/commands/npm-trust                                                         |
| Patch delivery to consumers | Vite plugin (`transform` plus `optimizeDeps.rolldownOptions`): +675 B against +13.1 MB for `bundledDependencies` and about 1.0 MB gzipped for an in-tree copy; an install script is excluded                                                                                                                          | `allowBuilds` policy in `pnpm-workspace.yaml`                                                             |
| Not adopted                 | GitHub's workflow lockfile (`actions.lock`): public preview since 2026-10-14, known here only from secondary sources — revisit when documented                                                                                                                                                                        | web search 2026-11-06                                                                                     |
