# SL-061 — Every shipped capability has a live page in biac's own docs project

Milestone: Phase 8 — Documentation site · State: open · Depends on: SL-060 (shipped) · Closes: GAP-064, GAP-070, GAP-071

## Outcome

A person new to biac opens the docs project, follows Getting started from install to a built page, and finds one page per shipped widget, filter and feature that shows the markup and runs it on real data — the site itself built by `biac build docs`, readable at 375 px and in dark mode; every guide (the AWS deployment guide included) lives there and nowhere else.

## Demo

1. Cold start: `bin/biac dev docs`, open `/` — "What is biac"; the sidebar lists What is biac and Getting started, then the sections Pages · Data · Widgets · Layout · Filters · Cross-filter · Ship.
2. Open `/getting-started` and follow it in a fresh directory: `biac dev` → first page → first chart → `biac build` → `biac preview` — every command and file in the tutorial works as written.
3. Open `/components/bar-chart`: a live bar chart on the docs data, then the `mdx echo` markup that produced it; every other widget and filter page renders the same way (one per `mdxComponents` tag group).
4. Open `/filters/dropdown`, pick a value — the widgets on the page re-query and the URL carries it; reload — the pick persists.
5. Open `/deploy-on-aws` — the guide is served from `docs/`; `bin/biac dev` (the example project) no longer lists it.
6. Resize to 375 px and switch to dark: no page scrolls sideways, code fences scroll inside themselves, every chart re-themes.
7. Stop the server, `bin/biac build docs` — exit 0, the ADR-0034 link check passes, `bin/biac preview docs` serves the same pages.
