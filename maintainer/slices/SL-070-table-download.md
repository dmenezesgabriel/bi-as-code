# SL-070 — A reader downloads the rows a table shows as a CSV file

Milestone: Phase 10 — Table extras · State: open · Depends on: SL-004 (shipped) · Closes: GAP-100

> Delete this file when the slice ships.
>
> Every path below was checked with `test -e` on 2026-11-11 and every reference file was opened that day. Line ranges are omitted on purpose. No external URL is cited: every claim comes from the four references or from `src/`.

## Outcome

A reader of any page that shows a table clicks one Download button above or beside it and saves every row of that table, in the order and with the headers it shows, as a CSV file that opens in Excel with accents intact.

## Demo

1. Cold start: `bin/biac dev`, open `/weekly-review` (its `weekly_trend` `<Table>` has 39 rows over 4 pages, per `test/e2e-browser/table-widget.spec.ts`).
2. The table shows one Download button, labelled `Download CSV` for assistive tech, with the pager's 24 px target size at minimum.
3. Click a column header to sort it, click Download: the browser saves `weekly_trend.csv`. Open it: a header row with the column titles shown on screen, 39 data rows (not the 10 on the current page), in the sorted order, numbers as plain digits (`6100`, not `6.1k` or `$6,100`), dates as ISO text.
4. Open the same file in a spreadsheet: accented characters are intact.
5. Narrow the page with a filter (`/weekly-review?region=West`): the download holds only the filtered rows.
6. A table with zero rows shows the empty state and no Download button.
7. `bin/biac build` + `bin/biac preview`: the button works on the static site, no server involved.

## Trade-offs and what we adopt

| Axis                | Options seen (repo → approach)                                                                            | Trade-off                                                                                                                                                 | Our choice, and why                                                                                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Surface             | evidence and streamlit → button on the table; both also → standalone tag/widget                           | A table-attached button needs no new tag, no props and no query. A standalone one needs a `data`, label, filename and its own filter wiring.              | The button on the table only. It is the intersection of both references and needs no author action. The standalone `<Download>` stays `later`.                               |
| Format              | evidence → `.xlsx`; streamlit → `.csv`                                                                    | `.xlsx` needs a spreadsheet-writing dependency, a new supply-chain surface behind the wrap-site rules in `AGENTS.md`. CSV is a string.                    | CSV, no dependency. Evidence's own unused `convertToCSV` shows CSV is the cheap path.                                                                                        |
| Cell value          | evidence → raw value with a style; streamlit → raw value                                                  | Formatted text (`$6.1k`) cannot be summed or re-parsed. A CSV has no cell style to carry the format.                                                      | The raw value: a number as its digits, a `bigint` as its digits, a `Date` as ISO 8601 (`toISOString`), `null` and `undefined` as an empty cell, a boolean as `true`/`false`. |
| Columns and headers | evidence → shown columns, titles; streamlit → shown columns, names                                        | The reader asked for what they see; a column hidden by `<Column>` children must not leak. Titles read better than ids.                                    | The columns the table shows (`columns ?? defaultTableColumns(rows)` in `data-table.tsx`), in that order, headed by `TableColumn.title`.                                      |
| Row order and scope | evidence → sorted rows, all of them; streamlit → the grid's rows                                          | Exporting only the visible page would hide 29 of 39 rows. Exporting the unsorted rows would ignore the sort the reader just chose.                        | Every row, in the current sort order (`sorted` in `data-table.tsx`).                                                                                                         |
| Quoting and Excel   | evidence → quote everything; streamlit → minimal quoting plus a BOM                                       | Quote-everything makes numbers read as text in some importers. Without a BOM Excel mis-decodes UTF-8.                                                     | Streamlit's: quote only a cell with `,`, `"`, `\r` or `\n`, double the quote, join rows with `\r\n` and start the file with `﻿`.                                             |
| Save mechanism      | evidence → Blob + anchor; streamlit → `showSaveFilePicker` then Blob + anchor                             | The picker needs a package (`native-file-system-adapter`) and a fallback; Blob + anchor works in every browser Playwright drives and on the static build. | Blob + anchor, revoke the object URL after the click.                                                                                                                        |
| File name           | evidence → `table_data` or the title; streamlit → timestamp                                               | A timestamp makes the e2e assertion non-deterministic. A fixed `table_data` collides across tables on one page.                                           | `<fence name>.csv`, the `data` the table reads (`weekly_trend.csv`).                                                                                                         |
| Opt-out             | evidence → none; streamlit → config switch                                                                | A prop is an option; this slice ships none.                                                                                                               | No opt-out. Revisit if a real use case appears.                                                                                                                              |
| Empty table         | evidence → no button (`hasData`); streamlit → no action (`isEmptyTable` in `useDataFrameCapabilities.ts`) | A header-only file is noise. Both references agree.                                                                                                       | No button: `DataTable` already returns `TableEmpty` before any chrome renders.                                                                                               |

## Deviations

| Deviation                                       | Why                                                                                                         |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| CSV only, no `.xlsx`                            | A spreadsheet writer is a new dependency with its own supply-chain surface; CSV opens in every spreadsheet. |
| No standalone `<Download>` tag, no `limit` prop | Our rows are already in the browser; there is no query to limit. The tag stays `later`.                     |
| No `showSaveFilePicker`                         | A new package and a fallback path for no gain a reader can see.                                             |
| Raw values, not display text                    | A CSV carries no cell style; formatted text loses the number.                                               |

## Open decisions

| Decision                                                                                                                                                                                                                       | Evidence, then the outcome                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What a `Date` cell holds: a date or a timestamp, and whether `toISOString` keeps a time the table hides                                                                                                                        | Decided in T1: the full `toISOString()` (`2026-01-05T00:00:00.000Z`). Lossless, and a `Date` cannot tell a DATE from a midnight TIMESTAMP. Cells arrive as UTC-clock `Date`s (`src/web/src/features/data/to-rows.ts`).       |
| A cell that begins with `=`, `+`, `-` or `@` opens as a formula in a spreadsheet; neither reference neutralises it                                                                                                             | Decided in T1: no prefix. Neither reference neutralises, the rows are the author's own result, and the output is unchanged, so no ADR. Stated in the `toCsv` JSDoc.                                                          |
| Whether to cap the export: streamlit hides it above 150000 rows (`research_repos/streamlit/frontend/lib/src/components/widgets/DataFrame/hooks/useDataFrameCapabilities.ts`), evidence caps only the standalone tag's re-query | Measured in T1: `toCsv` on 200000 rows × 8 columns (mixed text, numbers, dates) takes 1379–1785 ms over 3 runs and writes 23444461 characters (`node --experimental-strip-types`, host load ~8 of 8). No cap.                |
| Whether `bigint` columns beyond `Number.MAX_SAFE_INTEGER` need anything                                                                                                                                                        | Decided in T1: `String(value)`, exact. `src/web/src/features/data/duckdb-query-casts.ts` sets `castBigIntToDouble`, so a DuckDB `BIGINT` reaches `Row` as a `number`; the `bigint` branch only covers a `Row` built by hand. |
