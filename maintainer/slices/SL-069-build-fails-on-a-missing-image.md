# SL-069 — `biac build` fails on an image no file serves

Milestone: Known debt (Phase 8's `biac build` link check, ADR-0034, is the precedent) · State: open · Depends on: — · Closes: the Known-debt row "`biac build` does not check an image" (it has no `GAP-NNN`)

> Written 2026-11-11. Delete this file when the slice ships.

## Outcome

A page that shows an image no file serves — `![alt](/data/gone.png)` — stops `biac build` with the page file, the line and the path, the way a broken page link already does, instead of shipping a broken image.

## Demo

1. Cold start: `bin/biac dev docs`, open `/pages/markdown-pages`; the Images section shows `/data/page-routes.svg`.
2. Add `![gone](/data/gone.png)` to `docs/pages/pages/markdown-pages.md`. `biac dev` still renders the page, with a broken image (dev is unchanged).
3. `bin/biac build docs` exits 1 and prints `1 broken image — each must name a file biac serves:` then `pages/pages/markdown-pages.md:<line> → /data/gone.png (no file at data/gone.png)`. No `docs/build/` is written.
4. Change it to the reference style `![gone][img]` plus `[img]: /data/page-routes.svg`; the build passes (the definition is not reported as a broken page link).
5. Point it at a loader target (`/data/island-summary.csv` is generated by `docs/data/island-summary.csv.js`): the build passes. Point it at `/data/island-summary.csv.js` (the loader source is never copied): the build fails.
6. Remove the line; `bin/biac build docs` passes and `bin/biac preview docs` serves the Images section with the image loaded.

Write this PRD to be grepped: no hard-wrapped paragraphs, one fact per table row, full file names, and no `GAP-NNN` is invented — the debt row is the source of truth.

**Count:** 2 of 4 fail on a missing image, and the 2 that do not are a tag validator that cannot see the disk (evidence) and a project with no pages (mosaic). The one static-site generator that copies referenced files (framework) fails the build on a missing one. Failing is the common behavior wherever the tool reads the file at all, so the check is worth building and is not an invention.

## Trade-offs and what we adopt

| Axis                | Options seen                                                                                                    | Trade-off                                                                                 | Our choice, and why                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Fail or warn        | framework fails on a file, warns on a link; evidence does neither                                               | A typo blocks a deploy, against a broken image shipping                                   | Fail, like ADR-0034: the same reasoning (the build is the last step before a deploy) and the same error shape  |
| Where it runs       | `buildStart`, over each page's parsed tree (ADR-0034) · after bundling over the emitted HTML                    | The SPA shell holds no page markup, so only the first sees images                         | `buildStart`, right after `assertInternalLinksResolve`, build only                                             |
| What exists         | the `data/` tree as copied (`copyDataDir` skips loader sources) · plus loader targets (`listDataLoaderTargets`) | A loader output is generated after `buildStart`'s check unless targets are listed         | The `data/` tree files that are not loader sources, plus `listDataLoaderTargets`: the set the built site ships |
| Relative `src`      | reject (ADR-0034 for `href`) · resolve against the page route                                                   | One `src` has two targets depending on the trailing slash                                 | Reject with the ADR-0034 reason, so the rule an author learns for links is the rule for images                 |
| Other root-relative | check against the disk · report                                                                                 | `/x.png` outside `data/` is served by nothing (`publicDir` is not set anywhere in `src/`) | Report `only data/ is served`, because a root-relative path that names no served file is broken the same way   |
| One compile or two  | a second `compile` per page for images · one collector that returns links and images                            | Each page is compiled once more per pass (0.29 s on 10 pages for links alone, ADR-0034)   | One collector pass returns both, so the cost does not double and `jscpd` stays clean                           |

## Deviations

- framework warns for a broken page link and fails for a missing file; we fail for both (ADR-0034, this slice).
- framework resolves relative `src` against the page; we reject a relative `src` with the same reason as a relative `href`.
