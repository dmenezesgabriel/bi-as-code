# ADR-0031 — Single sign-on is a proxy in front of a private bucket, and biac reads no identity

Status: accepted
Date: 2026-10-26
Relates to: [ADR-0005](0005-queries-run-client-side-in-duckdb-wasm.md), [ADR-0029](0029-the-build-copies-its-shell-per-route-and-honors-an-absolute-base.md), [ADR-0030](0030-biac-serve-is-env-basic-auth-that-fails-closed-beyond-localhost.md)

## Context

ADR-0029 made `build/` servable by any rewrite-less static host, and ADR-0030 gave `biac serve` one shared basic-auth pair and left per-user sign-in to "an upstream proxy". A deployer still needs evidence that a static build works behind real single sign-on, in the shape they run on AWS (a private bucket behind a load balancer that authenticates), and a copyable configuration. That evidence is `examples/s3-sso/`: one compose file, `pnpm -s example:s3-sso:smoke` to prove it, and a README with the AWS mapping.

The facts that bind the design:

- S3's REST API serves no index document. A request for `<route>/` is a missing key, and a reader without `s3:ListBucket` gets `403` for a missing key where moto answers `404`. moto stores a bucket's website configuration but serves neither its index nor its error document, measured with `get-bucket-website` and signed `GET`s against `motoserver/moto:5.2.4`.
- moto authenticates nothing unless `INITIAL_NO_AUTH_ACTION_COUNT` is set, and then skips that many requests before authenticating every later one (https://docs.getmoto.org/en/latest/docs/iam.html). With `0`, no credential can be created at all. moto's bucket policies honour only `Principal: *` statements and ignore conditions (https://docs.getmoto.org/en/latest/docs/services/s3.html), so the `aws:SourceVpce` policy AWS uses for a private bucket behind a load balancer would make moto's bucket public.
- Caddy's `forward_auth` lets a request continue on a `2xx` from the gate and copies any other response back to the client (https://caddyserver.com/docs/caddyfile/directives/forward_auth). oauth2-proxy documents that integration: `/oauth2/*` proxied, `forward_auth … uri /oauth2/auth`, a `401` turned into a redirect to `/oauth2/sign_in`, `reverse_proxy = true` (https://oauth2-proxy.github.io/oauth2-proxy/configuration/integrations/caddy).
- An ALB's `authenticate-oidc` action runs only on an HTTPS listener, signs only the `x-amzn-oidc-data` header, and with `OnUnauthenticatedRequest: deny` answers `401` only to requests that carry no session (https://docs.aws.amazon.com/elasticloadbalancing/latest/application/listener-authenticate-users.html). A listener rule's `url-rewrite` transform rewrites a path by regex without a redirect (https://docs.aws.amazon.com/elasticloadbalancing/latest/application/rule-transforms.html).
- oauth2-proxy's `entra-id` provider takes the issuer `https://login.microsoftonline.com/<tenant-id>/v2.0` and restricts access with `allowed_groups` (https://oauth2-proxy.github.io/oauth2-proxy/configuration/providers/ms_entra_id). No self-hosted identity provider serves Entra's issuer, so a local run needs a stand-in.
- Every query runs in the viewer's browser over files fetched from `data/` (ADR-0005), so anyone who can load a page can download all of its data.

## Decision drivers

- biac ships no authentication code beyond ADR-0030. Sign-in, sessions and roles belong to infrastructure the deployer already runs.
- The bucket is private in fact, not by convention: an unsigned read from inside the network is refused.
- Each local piece maps onto a managed AWS piece, and the Terraform is the file a deployer would apply.
- Every URL the app writes is served: deep links, reloads with a query string, and a real `404` for a miss.
- The run is reproducible: images pinned by digest, no durable state, and one command that proves it.

## Options considered

| Axis                          | Option                                                              | Pro                                                                                                                             | Con                                                                                                      |
| ----------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Where sign-in happens         | An authenticating proxy in front of the static files                | No biac code; the same build serves every deployment; ALB, oauth2-proxy and Entra all speak it                                  | One more hop to configure                                                                                |
| Where sign-in happens         | OIDC inside biac (a login route, a session)                         | One process                                                                                                                     | biac would need a server, so the static build could no longer deploy alone; secrets and sessions in biac |
| How the edge reads the bucket | A SigV4 signing proxy holding a key that grants only `s3:GetObject` | Every read is authenticated, which moto enforces; the edge holds no key                                                         | One more container                                                                                       |
| How the edge reads the bucket | A bucket policy with an `aws:SourceVpce` condition                  | The AWS production pattern                                                                                                      | moto ignores conditions, so the bucket would be public                                                   |
| How the edge reads the bucket | A public-read bucket                                                | Simplest                                                                                                                        | Not private                                                                                              |
| Directory index               | A proxy rewrite `<route>/` → `<route>/index.html`                   | One line; matches S3 REST and an ALB `url-rewrite`                                                                              | The proxy owns a routing rule                                                                            |
| Directory index               | The bucket's website endpoint                                       | The real-S3 behaviour                                                                                                           | moto does not serve it; on AWS it is HTTP-only and public                                                |
| Directory index               | A redirect to `<route>/index.html`                                  | Supported by every ALB listener                                                                                                 | The address bar shows `index.html`, which is not a route the app knows                                   |
| Provisioning                  | Terraform's AWS provider pointed at moto                            | The production file with one provider block swapped                                                                             | Slower than a sync (one resource per file)                                                               |
| Provisioning                  | `aws s3 sync`                                                       | One command                                                                                                                     | Nothing a deployer would keep                                                                            |
| Identity provider             | Keycloak with a realm shaped like an Entra tenant                   | Realm ≈ tenant, client ≈ app registration, client role ≈ app role; claims mapped to `oid`, `tid`, `preferred_username`, `roles` | Not Entra's URLs; production swaps the oauth2-proxy provider                                             |
| Issuer origin                 | Keycloak on the app's origin under `/realms/*`                      | One `iss` for the browser and the back channel; no second certificate or port                                                   | oauth2-proxy cannot fetch discovery at `localhost`, so its endpoints are listed by hand                  |
| Issuer origin                 | Keycloak on its own published port                                  | Discovery works                                                                                                                 | A second published port and certificate; the issuer differs between the browser and the containers       |
| Return URL after sign-in      | `rd` = the escaped request URI, relative                            | Keeps the port and the query string; needs no redirect domain allowed                                                           | Departs from the upstream example                                                                        |
| Return URL after sign-in      | The upstream `{scheme}://{host}{uri}`                               | Copied verbatim                                                                                                                 | `{host}` drops `:8443`, and `&` in the query is left unescaped                                           |

## Decision

A biac project gets single sign-on from a proxy in front of its static `build/`. biac reads no identity: no `X-Forwarded-User`, no `x-amzn-oidc-*`, no cookie. The supported shape is `examples/s3-sso/`:

- **Bucket** (`compose.yaml`, `terraform/main.tf`, `bootstrap.sh`): moto with `INITIAL_NO_AUTH_ACTION_COUNT=3`. The three free calls create a `deployer` IAM user, its key and an admin policy. `terraform apply` as `deployer` then creates the bucket, Block Public Access, the website configuration (for parity), a reader user whose only grant is `s3:GetObject` on the bucket's objects, and one `aws_s3_object` per build file with `content_type` by extension. Changes are tracked by `source_hash`, not `etag`, because a multipart upload's ETag is not an MD5. A file whose extension has no media type fails the plan.
- **Signer** (`compose.yaml`): `aws-sigv4-proxy` signs every read with the reader key. The key reaches it through a volume that is never bound to the host.
- **Edge** (`Caddyfile`): Caddy with its internal CA on `localhost:8443`, HTTP on `:8080` redirecting to HTTPS. `/realms/*` and `/resources/*` go to Keycloak and `/oauth2/*` to oauth2-proxy. Every other request first passes `forward_auth` to `/oauth2/auth`, where a `401` becomes a redirect to `/oauth2/sign_in?rd=<escaped request URI>`. Then `*/` is rewritten to `*/index.html` and the request is proxied to the signer under the bucket prefix. A bucket `403` or `404` becomes the build's `404.html`, served with status `404`.
- **Gate** (`oauth2-proxy.cfg`): provider `keycloak-oidc`, PKCE `S256`, `allowed_roles = ["biac-dashboard:Dashboard.Viewer"]`, `reverse_proxy = true`, `skip_provider_button = true`. The issuer is the edge URL, with the login URL on the edge and the token and key endpoints on the compose network.
- **Identity provider** (`keycloak/realm.json`, `compose.yaml`): Keycloak imports realm `biac` on every start, with `KC_HOSTNAME=https://localhost:8443` and `KC_HOSTNAME_BACKCHANNEL_DYNAMIC=true`, so every token's `iss` is the edge URL. The admin console is not routed.
- **Pins and exposure**: every image is pinned by tag and digest. Only Caddy publishes ports, on `127.0.0.1`. Nothing is durable: `down -v` removes the bucket, the keys, the realm and the state.
- **Proof**: `pnpm -s example:s3-sso:smoke` (`examples/s3-sso/smoke.sh`, `smoke.ts`) brings the stack up, asserts the `302`, `308` and unsigned `403`, signs in headless, loads a deep link with a query, re-queries on a filter, reloads, opens a nested route directly, requires a clean console, and tears down on every exit path. It needs Docker and image pulls, so it stays outside `pnpm gate`.

## Consequences

- A static build deploys behind SSO with no biac change. The README maps each local service to its AWS counterpart (ALB listener + `authenticate-oidc`, a `url-rewrite` transform, an S3 interface endpoint + `aws:SourceVpce`), and swapping `keycloak-oidc` for `entra-id` is a provider change.
- Access is all or nothing. Every signed-in viewer can download every file under `data/`; one audience per build is the only way to scope data.
- A viewer whose proxy session expires while the identity provider's lives notices nothing: the next request through the edge renews it with redirects and no form. With both expired, filters on loaded data keep working, an in-app navigation to an unvisited page shows "This page failed to render" (its script request lands on the sign-in HTML), and a reload signs in and returns to the page. An ALB redirects an expired session the same way, so biac needs no code for it.
- duckdb-wasm loads its parquet extension from `extensions.duckdb.org`, the one browser request that does not pass the edge.
- The local CA has no volume, so it is new after every `down`. Trusting it is the host's choice, and headless runs ignore certificate errors.
- moto is labelled a local demonstration and is never a production store. Its authentication is basic, and its policy engine cannot express the production rule, which is why a signer stands in for the VPC-endpoint path.
