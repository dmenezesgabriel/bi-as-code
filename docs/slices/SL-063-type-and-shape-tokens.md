# SL-063 — A project sets its fonts, type size, corner radius and semantic colours, and a page overrides them

Milestone: Phase 4 — Project and page settings, themes, layouts · State: open · Depends on: SL-048 · Closes: GAP-068

## Outcome

An author writes `brand: { fonts: { body, heading, code }, fontSize, radius }` and `brand.colors.{ positive, negative, field, sidebar }` in `biac.config.ts`, and the page text, headings, code fences, charts, deltas, input controls, sidebar and every rounded corner follow them; the same keys in a page's front-matter override the project for that page. A value outside its bounds or a colour under its contrast floor is a located error that fails `biac build`, as `brand.colors` already does ([ADR-0018](../adr/0018-brand-colours-are-contrast-checked-config-not-a-theme.md)).

## Scope set by the author (2026-10-19)

| `brand.fonts` takes `body`, `heading`, `code`, each one of `sans-serif` \| `serif` \| `mono` — system stacks only                                                                                          | No font files, no third-party request (research D7 in `docs/research/settings-and-themes.md`)                                                                                            |
| `brand.fontSize` scales the whole rem scale: it sets the root font size, so text, spacing, `--container-measure` and the radius scale together                                                             | The reading measure stays 70ch at any size; evidence's text-only multiplier is not ported                                                                                                |
| Every non-colour value is bounded: `fontSize` a px value in a range, `radius` a length from 0 to a cap; outside the bounds is a located `ConfigFieldError` (`src/engine/biac-config-error.ts` `invalid()`) | Ranges are settled with evidence in O2 and O3                                                                                                                                            |

## Demo

1. Cold start: `bin/biac dev` at 1440×900. On `/weekly-review`, `eval` shows the baseline measured 2026-10-19: root `font-size` `16px`; `body` and `main h1` `font-family` `ui-sans-serif, system-ui, sans-serif, …` (Tailwind's `--font-sans`); a `pre` `ui-monospace, SFMono-Regular, …` at `14px`; `--radius` `0.5rem` and a select trigger `border-radius` `6px`; the `+9.9%` delta `rgb(0, 120, 79)` (`--positive` `#00784f`); `--field` `#ffffff` / `#171717`, `--sidebar` `#fafafa` / `#171717`, `--positive` `#00d492` and `--negative` `#ff6467` in dark. A paragraph's `max-width` is `640px`. Chart axis labels draw in ECharts' own `sans-serif`, not the page's stack (visible in a screenshot of `/orders-dashboard`).
2. Add `brand: { fonts: { body: "serif", heading: "sans-serif", code: "mono" } }` to `biac.config.ts` and save. The tab reloads by itself. Body text and the chart axis labels are serif; headings stay sans; a SQL fence stays mono.
3. Add `fontSize: "18px"`. Root `font-size` is `18px`, a paragraph's `max-width` is `720px` (still 40rem = 70ch), and the select trigger's radius grows with it. Browser zoom to 200% still reflows (WCAG 2.2 SC 1.4.4).
4. Add `radius: "0"`. Every input, card and chip corner is square; `--radius-sm` does not go negative.
5. Add `colors: { positive: { light: "#047857", dark: "#34d399" }, sidebar: { light: "#f1f5f9", dark: "#0f172a" } }`. The delta and the sidebar take them in both modes.
6. Set `fontSize: "10px"`: the overlay names `brand.fontSize`, the value and the accepted range at `biac.config.ts:<line>:<column>`. Set `positive.light` to `#4ade80`: the overlay names the pair, ratio and floor. Restore both and the page returns.
7. `pages/crossfilter-scale.md` front-matter sets `brand: { fonts: { body: "sans-serif" }, radius: "1rem" }`. That page alone is sans with round corners; navigate to `/` and back — each page shows its own.
8. Reload — the effect persists. `pnpm build && pnpm preview` shows the same.

## Deviations

- No font files: `serif` maps to a system stack, not Source Serif 4 or Spectral. A comment at the stack constant says why (a third-party or bundled font request on every page).
- No silent fallback: out-of-range values are errors (ADR-0018 precedent).
- No `sidebarFontSize`, `depth`, `chart.*`/`table.*` toggles (research D7).

## Open decisions

Default ratios below were measured 2026-10-19 with `src/engine/contrast-ratio.ts` `contrastRatio` on the `src/web/src/styles.css` values.

- **O1 — contrast pairs for the four colours.** Proposed, each in both modes:
  - **Settled (T1):** `--positive`, `--negative` against `--background`, `--card` and `--card-mode-background` at 4.5:1 (SC 1.4.3), and against their own 10% chip over each surface (`src/engine/contrast-ratio.ts` `blendOver`, `src/engine/brand-contrast.ts` `CHIP_TINT`). The default light `--positive` `#007a55` measured 4.47:1 on its chip over `--card-mode-background`, so it became `#00784f` (4.60).
  - **Settled (T2):** `--field` against `--foreground` (light 17.93, dark 16.44) and `--muted-foreground-faded` (placeholder, 4.74 / 6.94) at 4.5:1. Not against `--input` (1.48 / 1.73) or as the toggle thumb on `--secondary` (1.26 / 1.73) at SC 1.4.11: the defaults already miss both, the label and placeholder identify the control; the reason is a comment at `CONTRAST_PAIRS`.
  - **Settled (T2):** `--sidebar` against `--foreground` (17.18 / 16.44), `--sidebar-foreground` (9.93 / 12.09) and `--muted-foreground` (7.49 / 6.94) at 4.5:1, and against `--ring` at 3:1 (SC 2.4.13, sidebar links draw their ring inside; 4.54 / 6.94). The active link's `bg-sidebar-accent/60` chip is not a pair: an RGB sweep at step 3 in both modes found no sidebar colour that passes the plain pairs and fails `--foreground` or `--ring` on the chip, which holds while `--sidebar-accent`, `--foreground` and `--ring` are not brand keys.
  - Each adds names to `ThemeTokenName` and `DEFAULT_THEME_TOKENS`, whose drift test keeps them equal to `src/web/src/styles.css`. Settle in T1/T2 by grepping every utility on `bg-field`/`bg-sidebar`/`text-positive`/`text-negative`.
- **O2 — `fontSize` range and emission. Settled (T4):** a `"<n>px"` string, `n` a whole number from 12 to 24 inclusive; rem and decimals are not accepted. `src/engine/brand-css.ts` `rootDeclarations` writes `font-size: <n/16 × 100>%` into the fonts' `:root` rule, so a reader's own browser size still scales it (C12, https://www.w3.org/WAI/WCAG22/Techniques/css/C12). Out of range is `brand.fontSize: expected a "<n>px" size, n a whole number from 12 to 24, got "10px"` at the key (`biac.config.ts:7:12` in `test/e2e-browser/brand-theme.spec.ts`). Measured 2026-10-19 on `/weekly-review` at 1440×900, 16px → 18px: root `font-size` 16px → 18px, a paragraph's `max-width` 640px → 720px, a select trigger's radius 6px → 7px, `main` scroll height 6291px → 7590px; at 720×450 no horizontal scroll. Chart canvases (300px) and their axis labels are px and do not scale.
- **O3 — `radius` units and cap.** Proposed: `"<n>px"` or `"<n>rem"`, from 0 to 1.5rem/24px (streamlit's largest step, `full`, is 1.4rem). `--radius-sm` is `calc(var(--radius) - 4px)`; check in a browser that a 0 radius computes `0px`, not a dropped declaration (CSS clamps a `calc()` result to the property's range, https://www.w3.org/TR/css-values-4/#calc-range). `rounded-full` pills stay pills.
- **O4 — which stacks. Settled (T3):** Tailwind's `--font-sans`, `--font-serif`, `--font-mono`, so the defaults render as before. `src/web/src/styles.css` names them `--font-stack-sans-serif`/`-serif`/`-mono` and points `--body-font`, `--heading-font`, `--code-font` at them; `@theme inline` sets `--default-font-family`, `--default-mono-font-family` and a `font-heading` utility from those. The brand writes `--<key>-font: var(--font-stack-<name>)` in one `:root` rule (`src/engine/brand-css.ts` `fontDeclarations`). Measured: before T3 the built CSS emitted no `--font-serif` (Tailwind drops an unreferenced theme var); naming the stacks makes it emit, held by `test/e2e/static-build.e2e.test.ts`.
- **O5 — charts follow the body font. Settled (T3):** yes. `readChartTokens` reads `--body-font` into `ChartTokens.fontFamily` and `chartTheme` sets the root `textStyle.fontFamily`; `test/e2e-browser/brand-theme.spec.ts` reads it off the live option.
- **O6 — page override depth.** Proposed: every new key per page, key by key, as ADR-0018 does for colours: a page's `fonts.body` alone leaves the project's heading and code fonts. `fontSize` per page changes the root while the page is mounted, as the brand style already does for `--background`.

Each decision is recorded by amending ADR-0018 (or a new ADR if fonts and size warrant one) in T6.
