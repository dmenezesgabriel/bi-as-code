# SL-044 — Data loaders in Python, shell and TypeScript, plus an `interpreters` map

Milestone: Phase 3 — Data loaders · State: partial — awaits its demo · Depends on: SL-042, SL-043 · Closes: GAP-038

## Outcome

A user can write a data loader in Python (`data/<name>.<ext>.py`), shell (`.sh`), TypeScript (`.ts`) or any of framework's 12 default languages, add or disable a language through `interpreters` in `biac.config.ts`, and get the same behaviour a `.js` loader has today: run on first request and cached in dev, run at build with only the output shipped, the source never served, a failure located in the page and the log, and an edit refreshing the open page.

## Demo

1. Cold start: `bin/biac dev`, open `/regional-orders`. Its tables come from `data/region-revenue.csv.py` and `data/daily-orders.csv.sh`; the dev log shows one run line per loader, each naming its file, output size and duration.
2. `curl -i http://localhost:5175/data/region-revenue.csv.py` and `.../daily-orders.csv.sh` → `404`. `curl -i .../data/region-revenue.csv` → `200 text/csv`, the Python loader's stdout.
3. Edit the `.py` loader so it emits different figures and save: the open page shows them with no reload (`window.__mark` set before the edit is still `1`).
4. Break it (`raise SystemExit(3)` at the top) and save: the page shows the located error (`data loader data/region-revenue.csv.py exited with code 3, expected 0`). Restore it.
5. In `biac.config.ts` set `interpreters: { ".py": null }` and save: `/data/region-revenue.csv` → `404` and the page shows that table as unreadable. Remove the line: it comes back.
6. Add a second loader for the same target (`data/region-revenue.csv.js` beside `data/region-revenue.csv.py`): `/data/region-revenue.csv` answers `500` naming both files. Delete it.
7. `bin/biac build`: exit 0, `find build/data -name '*.py' -o -name '*.sh' -o -name '*.ts'` prints nothing, `build/data/region-revenue.csv` and `build/data/daily-orders.csv` hold the outputs. `bin/biac preview`: the page renders the same figures.
8. Stop `bin/biac dev`, set `interpreters: { ".py": ["python-missing"] }`, `rm -rf .biac/cache` (a cached output newer than its loader is reused without a run, so a warm cache never reaches the interpreter) and `bin/biac build`: exit 1, `data loader data/region-revenue.csv.py could not start: command "python-missing" not found on PATH`. Restore the config.

## Trade-offs and what we adopt

| Axis                        | Options seen (repo → approach)                                    | Trade-off                                                                                                                                                                       | Our choice, and why                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 Default interpreters     | framework → 12 defaults; the slice row names only `.py .sh .ts`   | Each default is one table row on the same code path; every registered extension is also kept private, so more defaults also means fewer program files served by accident        | framework's 12 exactly: `.js .ts .py .r .R .rs .go .java .jl .php .sh .exe`, same argv except `.js`/`.ts` (D2). Decided by the user                                                                                                                                                                                                                                                                |
| D2 `.ts` runner             | framework → `tsx` from `$PATH`; Node 24 → built-in type stripping | `tsx` handles all TS syntax but is a dependency or a global install; Node strips types only (no `enum`, runtime `namespace`, parameter properties) and needs `.ts` import paths | Node's type stripping via `process.execPath`, as `.js` runs today: no dependency, no `$PATH` lookup. Stable since v24.12.0, no warning since v24.3.0 (https://nodejs.org/docs/latest-v24.x/api/typescript.html, fetched 2026-10-17), so `package.json` `engines.node` rises from `>=24.0.0` to `>=24.12.0`. A code comment names the unsupported syntax; a user who needs it maps `".ts": ["tsx"]` |
| D3 Two loaders, one target  | framework → first in map order, silently                          | Silent precedence hides a stale or duplicate loader; an error forces one owner per target                                                                                       | Located error naming every loader found: dev answers `500` with it, `biac build` fails before writing output. Decided by the user                                                                                                                                                                                                                                                                  |
| D4 Missing interpreter      | framework → raw `spawn ENOENT` error                              | Raw error names neither the loader nor what to install                                                                                                                          | A located error naming the loader and the command not found on `PATH`, surfaced like a non-zero exit (dev 500 + log, failed build) — the bar GAP-036 set                                                                                                                                                                                                                                           |
| D5 Which paths stay private | framework → only outputs are routable                             | Our `isDataLoaderSource` keys on `.js` alone today                                                                                                                              | Every extension in the effective table is program source: 404 in dev, never copied to `build/` — helper modules (`data/lib/x.py`) included. A disabled (`null`) extension becomes ordinary data again                                                                                                                                                                                              |
| D6 Interpreter keys         | framework → case-sensitive keys, `.r` and `.R` both listed        | Case-sensitive lookup matches the filesystem on Linux; the privacy check must not miss `x.PY` on a case-insensitive one                                                         | Lookup is case-sensitive on the key as written; the privacy check stays case-insensitive (as `isDataLoaderSource` is now)                                                                                                                                                                                                                                                                          |
| D7 Config edits in dev      | framework → config read once at server start                      | Re-reading lets `interpreters` edits apply without restart; our plugin already drops its memoized config on edit                                                                | Resolve the table from `getConfig()` (`src/engine/pages-plugin.ts`) per request and per build, so an edited map applies without restart                                                                                                                                                                                                                                                            |

## Deviations

- `.js` and `.ts` run with `process.execPath`, not `node`/`tsx` from `$PATH` (D2); stated in a code comment at the table.
- Two loaders for one target is an error, not first-match (D3); stated in a code comment at the check and in ADR-0017's amendment.

## Open decisions

None open: D1 and D3 were decided by the user in the session that wrote this PRD; D2 rests on the Node docs and the host probe (Node v24.18.0: `node a.csv.ts` → stdout, exit 0, empty stderr; a file with `enum` → exit 1 `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`; `import "./helper"` without `.ts` → `ERR_MODULE_NOT_FOUND`).

## Out of scope

- Archive loaders (`.zip.py`) and `[param]` loaders — not proposed for Phase 3 (`docs/research/data-loaders.md`).
- `--experimental-transform-types` for `enum`/`namespace` in `.ts` loaders — a user maps `".ts": ["tsx"]` instead.
- Installing interpreters or managing virtualenvs — the user's `PATH` decides, as in framework's §Execution.
- Windows: `.sh` needs `sh` on `PATH`, as framework documents; no win32 runner in this repo's gate.
