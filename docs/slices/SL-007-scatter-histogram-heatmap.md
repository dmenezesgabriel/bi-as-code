# SL-007 — `<ScatterChart>`/`<Histogram>`/`<Heatmap>`: correlation and distribution charts

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-006 · Closes: —

## Outcome

A page author writes `<ScatterChart data="by_week" x="orders" y="revenue" series="region" size="accounts" />` for a correlation plot, `<Histogram data="order_amounts" value="amount" binCount="20" />` for a distribution, and `<Heatmap data="weekly_trend" x="week" y="region" value="orders" />` for a density grid — each bound to a named ```sql fence's materialized rows, themed light/dark, with tooltip, legend and the shared loading/error/empty faces. No tag issues its own query; binning and pivoting run client-side over registry rows.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root, open `http://localhost:5175/weekly-review`.
2. "Order mix" shows `<ScatterChart data="region_week" x="orders" y="revenue" series="region" />`: one point per region-week, item tooltip naming region/orders/revenue on hover, `aria-label` on the chart container.
3. "Order size" shows `<Histogram data="order_amounts" value="amount" />`: ~355 orders binned into adjacent bars (rice-rule default), tooltip naming the bin range and count.
4. "Trend lines" gains `<Heatmap data="weekly_trend" x="week" y="region" value="orders" />`: week columns × region rows, cell shading by a continuous visualMap strip, item tooltip per cell.
5. Click the theme toggle — all three repaint in the dark palette (the heatmap scale re-anchors to the dark surface) without a reload; click back.
6. Open `http://localhost:5175/weekly-review?region=Atlantis` — every chart bound to a filtered-empty fence renders its empty state, not an error.
7. Point one chart's `data` at an undeclared name — inline `role=alert` names it; `x`/`y`/`series`/`value`/`size` typos name the column and list the available ones. Revert.
8. `console` stays clean throughout; no worker post fires after results settle (charts are registry reads).

**Named disagreements — the decisions this slice must make:**

- **Where binning/pivoting computes.** evidence (build-\*-sql) and mosaic (coordinator SQL) both push it into SQL; our fence owns SQL (SL-006 deviation, ADR-0005) → client-side pure transforms over registry rows. The evidence files above are the semantics to port, not the mechanism.
- **Histogram rendering.** evidence draws exact bin edges with a `custom` `renderItem` on a value x-axis (multi-series stacked); the alternative is a dense bin domain on a category x-axis with a `bar` series at `barCategoryGap: 0` — no new echarts component and identical look for equal-width bins. Decide in T2.
- **Scatter transform.** `toSeries` domain-pads every series and has no `size` slot; scatter wants sparse `[x,y,size?]` tuples and an item tooltip, not axis alignment.

## Deviations

- **No generated SQL** — `build-histogram-sql.ts`/`build-heatmap-sql.ts` are unported; binning and pivot run client-side over registry rows (the fence owns SQL — same constraint as SL-006's "no `build-chart-sql.ts`", grounded in ADR-0005).
- **No `y2`, `point_title`, `tooltip_fields`, `x_date_grain`, `filters`, `where`, `limit`, `x_sort`/`y_sort`/`value_sort`, `metric=`** — column names only; query semantics stay in the fence.
- **No `chart_options`/`echarts_options`/`echarts_series_options` escapes** — SL-006 precedent.
- **`heat_grid` and `calendar_heatmap` are separate tags** — the row names `<Heatmap>` only; both stay out (catalog rows own them).
- **`borders`, `legend_location`, `info`/`subtitle`, `flex`, sampling, connect-groups** — unported polish; additive props when a slice demands them.
- **Histogram renders on a dense category domain with a `bar` series** (interior empty bins exist as zero-height categories — required for alignment), not evidence's `custom` renderItem; `series` stacks.
- **`visualMap` is continuous only**; piecewise/calendared variants are later props.
- **Scatter keeps `labels`/`labelsFmt`** — the shared label path applies unchanged (position `top`).
- **`size` is a column name only** — streamlit's scalar form unported.

## Open decisions

- **Histogram axis shape** — dense category + `bar` (chosen above) vs evidence's value-x `custom` renderItem. Revisit if uneven-width bins are ever demanded; T2 confirms the category-label thinning is acceptable at ~20 bins via the story.
- **Scatter x-type on strings** — `inferXType` treats non-bar numeric x as `value`; a string `x` on scatter gets `category` (rare but legal). T1 unit-tests the inference matrix rather than forbidding it.
- **`min==max` visualMap** — all-equal values pin one color; verify echarts behavior in T3 (expect a single solid fill, not a crash).
- **Scatter `size` bounds** — evidence hard-codes max 35px/uniform 9px; adopt unless a demoed need says otherwise (named in T1 tests).
