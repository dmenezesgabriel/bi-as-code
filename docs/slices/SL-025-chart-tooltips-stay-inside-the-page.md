# SL-025 — A chart's tooltip never widens the page

Milestone: Phase 1 (Known debt) · State: open · Depends on: SL-006, SL-007 · Closes: Known-debt row "An ECharts tooltip left open by a hover keeps its position when the viewport shrinks, widening the page" (`docs/backlog.md`); no `GAP-NNN` (the R3 audit is closed and deleted)

## Outcome

A reader who hovers or taps any chart and then narrows the window, rotates the phone or opens devtools keeps a page that fits the viewport, and every tooltip they open is drawn whole inside its chart.

## Measured baseline (HEAD `cef0268`, `bin/biac dev`, headless `playwright-cli`)

The ledger row says the tooltip must be "left open". It does not: a tooltip that was shown once and then hidden widens the page just the same.

| Step                                                                                           | `scrollWidth` / `clientWidth` | Tooltip box                                                                                                                    |
| ---------------------------------------------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `/weekly-review` at 1280×720, Regional split scrolled to center, `mousemove 900 360`           | 1280 / 1280                   | 747..880 px, "South revenue: 3,700", in a 688 px host                                                                          |
| `resize 375 812` with the tooltip open                                                         | **592 / 375**                 | 459..592 px, still "South revenue: 3,700", in a 327 px host — off-screen                                                       |
| Same, but `mousemove 5 5` (tooltip hides) before the resize                                    | **592 / 375**                 | `visibility: hidden; opacity: 0; display: block` — invisible, still laid out at 459..592                                       |
| Fresh load at 375×812, hover the 6 charts at 3×2 points each (`fx` 0.1/0.5/0.92, `fy` 0.3/0.6) | 375 / 375                     | Area chart (`area chart of orders by week`) at `fx` 0.5: 15..168 px in a 24..351 host — **9 px outside its chart on the left** |

The overflowing element, found with `[...document.querySelectorAll('*')].filter(e => e.getBoundingClientRect().right > clientWidth + 1)`, is the echarts tooltip `<div>` inside the chart host. Console: 0 errors, 0 warnings.

### Why — read in `echarts@6.1.0` (the pinned production dependency, `src/web/package.json`)

- `node_modules/.pnpm/echarts@6.1.0/node_modules/echarts/lib/component/tooltip/TooltipHTMLContent.js` `hide()` sets only `visibility: hidden` and `opacity: 0`. The base CSS keeps `position:absolute;display:block`, and `moveTo` writes a transform that `hide()` never resets, so a hidden tooltip keeps its last box and counts toward the document's scrollable overflow.
- `.../tooltip/TooltipView.js` `render()` → `_keepShow()` re-shows the tip at the stale `_lastX`/`_lastY` after every re-render, including the one `resize()` triggers. `manuallyHideTip` (the `hideTip` action) clears `_lastX`/`_lastY`.
- `.../tooltip/helper.js` `shouldTooltipConfine` defaults to `false` for `renderMode: 'html'`. `TooltipModel.js` comments "If renderMode: 'html', defaults to `false` (for backward compat)".
- `TooltipView.js` `refixTooltipPosition` flips a tip left by `width + 20` when it would cross the right edge, with no lower bound. That is the area chart's 15 px left. `confineTooltipPosition` clamps to `[0, viewWidth - width]` × `[0, viewHeight - height]` of the chart.
- `TooltipView.js` maps `appendToBody: true` to `appendTo: 'body'`, so the tooltip node moves out of the chart host to `<body>`.

### Candidate fixes, measured on the live instance (`el.echartsInstance`, same 1280 → 375 script)

| Candidate                                                     | `scrollWidth` after resize | Fresh-load area-chart tip at 375 px                                      |
| ------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------ |
| none (today)                                                  | 592                        | 15..168, 9 px outside the host                                           |
| `setOption({ tooltip: { confine: true } })` only              | 592                        | — (not measured: the hidden tip still overflows, so confine alone fails) |
| `ResizeObserver` → `dispatchAction({ type: "hideTip" })` only | 592                        | — (hiding is `visibility: hidden`; the box stays laid out)               |
| host `overflow: hidden` + `confine: true`                     | **375**                    | inside the host (confine clamps x ≥ 0 of the chart)                      |
| host `overflow: hidden` only                                  | 375                        | 9 px of the tip clipped by the host edge                                 |

## Demo

1. Cold start: `pnpm build:cli` if `dist/cli/main.js` is older than `src/cli/`, then `bin/biac dev`. Open `http://localhost:5175/weekly-review` at 1280×720.
2. Scroll to Regional split and hover the South bar. The tooltip reads "South revenue: 3,700".
3. Narrow the window to 375 px: `document.documentElement.scrollWidth` is 375 (it was 592), and the page does not scroll sideways.
4. Back at 1280 px, hover the chart and then move the pointer off it. Narrow to 375 px: `scrollWidth` is still 375.
5. At 375×812, hover the middle of Orders by week (the area chart): the tooltip is drawn whole inside the chart box (its left edge ≥ the chart's left edge).
6. Repeat step 2–3 on the histogram, the scatter, the heatmap and `/crossfilter-scale`. The console stays clean (0 errors, 0 warnings).
7. `bin/biac build` + `bin/biac preview` (`http://localhost:4173/weekly-review`): steps 2–5 behave the same.

## Trade-offs and what we adopt

| Axis                         | Options seen (repo → approach)                                                                              | Trade-off                                                                                                                                                                                                                                                                                    | Our choice, and why                                                                                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Where the tooltip node lives | evidence page charts → `appendToBody: true`; evidence custom chart, streamlit, ours → inside the chart host | `<body>` escapes a clipping host, but a hidden tip at a stale page coordinate then overflows the document itself (the `hide()` mechanism above is the same); inside the host, clipping contains every leftover                                                                               | **Inside the host** (echarts default) — the only placement where the host's clip can contain the hidden leftover                                                                                             |
| Leftover hidden box          | evidence → `overflow-hidden` wrapper; streamlit, ours → nothing                                             | `overflow: hidden` makes the host a scroll container (still scrollable via `scrollLeft`/`scrollTo()` and focus); `overflow: clip` clips without one and supports no programmatic scrolling ([MDN `overflow`](https://developer.mozilla.org/en-US/docs/Web/CSS/overflow), fetched 2026-10-12) | **Clip the host.** Measured: 592 → 375. T1 picks `overflow-clip` vs `overflow-hidden` by checking that both keep the 375 result and that echarts' brush and hover still work; `clip` is preferred if they do |
| Visible tip near an edge     | evidence custom chart, CalendarHeatmap → `confine: true`; others → echarts' flip (`refixTooltipPosition`)   | Without confine, a clipped host cuts the flipped tip (area chart: 9 px). Confine clamps it inside the chart, but a tip wider than the chart would cover it — none is: widest measured 153 px in a 327 px host                                                                                | **`confine: true` once, in `chartTheme`** (`src/web/src/features/widgets/charts/theme.ts`), which every chart already inits with — no per-builder repetition                                                 |
| Stale tip after a resize     | evidence → hides on touch scroll, not on resize; echarts → `_keepShow` re-shows at the stale point          | With clip + confine, a re-shown tip stays inside the chart and names the datum under the old pointer position. Hiding on resize would add an observer path for a state the pointer corrects on its next move                                                                                 | **Not adopted** — measured fix holds without it (no workaround for a cosmetic state). Revisit only if T1's pass shows a stale tip pointing outside the plot                                                  |
| Touch dismissal              | evidence → `hideTip` on coarse-pointer `touchmove`/outside `touchstart`                                     | A separate behavior (tooltip stuck after a tap on phones), not this debt                                                                                                                                                                                                                     | Out of scope (below)                                                                                                                                                                                         |

## Deviations

- evidence's `appendToBody` is not ported. It exists to escape evidence's own clipping wrapper. Ours clips and confines, so there is nothing to escape, and `<body>` placement would re-open this exact overflow at the document level. The code comment at the host states the hidden-tooltip mechanism and cites `echarts@6.1.0` `TooltipHTMLContent.hide`.

## Open decisions

- `overflow-clip` vs `overflow-hidden` on the host: settle it in T1 by measurement (the `scrollWidth` script above, plus brush on Order size and point click on Regional split still publishing). No ADR is needed unless they differ in behavior.
