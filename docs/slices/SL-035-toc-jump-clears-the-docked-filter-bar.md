# SL-035 — A table-of-contents jump never lands its heading under the docked `<FilterBar>`

Milestone: Phase 2 — A polished UI · State: open · Depends on: — · Closes: GAP-017

> A PRD exists so the executing agent **never guesses and never assumes**. Every path below was checked on disk on 2026-10-15; every number carries the command that produced it.

## Outcome

On a page with a `<FilterBar>`, choosing any ToC entry (or opening a `#heading` link) lands that heading fully readable below the docked `Filters` row, and the rail lights the entry that was chosen.

## Demo

A numbered script a human runs from a cold start. The slice is not `shipped` until this has been run in the real app.

1. `pnpm build:cli && bin/biac dev --port 5535`, open `http://localhost:5535/weekly-review` at 1280×720.
2. Click every `On this page` entry in turn: each heading sits wholly below the docked `Filters` row, with the same gap under the row that a heading has under the header on a page without a bar; the rail lights the entry clicked.
3. Resize to 1280×1400 and repeat `Order mix` and `Quarter detail`: the rail lights `Order mix` and `Quarter detail` (today it lights `Order size` and `Takeaways`).
4. Resize to 375×812, open `/weekly-review#order-mix`, then `#takeaways`: each heading is readable below the docked row.
5. `/crossfilter-scale` → `Delay`, `Distance`, `Time`: same.
6. `/weekly-review?edit` at 1280 px, set the hash to `#takeaways` (the rail is hidden in the half-width pane): the heading clears the bar docked at the pane's `1rem`.
7. `bin/biac build && bin/biac preview` → `/weekly-review#order-mix`: same as step 2.

## Trade-offs and what we adopt

| Axis                   | Options seen (repo → approach)                                                                          | Trade-off                                                                                                                                    | Our choice, and why                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Where the offset lives | framework → `scroll-padding-top` on `:root`; evidence/streamlit/ours → `scroll-margin-top` on headings  | padding belongs to one scroller; our editor preview is a second scroller (`page-editor.tsx` `lg:overflow-y-auto`) whose `--dock-top` is 1rem | keep `scroll-margin-top` on `h2`/`h3`: it applies in whichever box scrolls, and `var(--dock-top)` already resolves per scroller                                                                                                                                                                                     |
| How big                | evidence → fixed 6rem; streamlit → header height, 0 gap; framework → header + 2.5rem; ours → fixed 5rem | a constant goes stale when the bar changes; ADR-0013 fixes the docked row at one height                                                      | `calc(var(--dock-top, 4rem) + <docked row height> + <gap>)`, the row height taken from the same source as `DOCKED_ROW_HEIGHT` in `filter-bar.tsx` (no second literal); gap = today's 2rem header→heading clearance (80 − 48 px) so bar and no-bar pages share one rhythm — 136 px at 4rem, 88 px in the editor pane |
| When it applies        | framework → `:has(#header)`; others → always                                                            | always-on wastes ~56 px above every jumped heading on pages with no bar                                                                      | only when the page has a `<FilterBar>`: `:has()` on the article for a marker the bar renders (e.g. `data-filter-bar`); else today's `scroll-mt-20`                                                                                                                                                                  |
| Rail after a jump      | framework/ours → hash wins in a fixed 0–40 px window                                                    | a fixed window breaks whenever the landing offset is not ~0 (framework has the bug too)                                                      | the window starts at the heading's own computed `scroll-margin-top` (read via `getComputedStyle` in `nav-toc.tsx`, passed to `pickActiveHeadingId`), so one offset drives both scroll and highlight                                                                                                                 |

## Deviations

- Framework puts the offset on the scroller; we keep it on the heading because the editor preview is its own scroller. Stated in a code comment at the rule.

## Open decisions

- Exact gap below the docked row (proposed 2rem, matching today's header clearance). Measure both 2rem and 1rem at 1280 and 375 px in T1 and keep the one where the heading reads as the section start, not the bar's caption.
- How the offset learns the row height: export a CSS custom property from `filter-bar.tsx` (e.g. `--docked-bar-height`) vs a shared TS constant interpolated into the class. Prefer whichever keeps one literal and passes Tailwind's static class scan.
