# SL-010 — `<Dropdown>` + `<MultiSelect>` with search

Milestone: Phase 1 · State: open · Depends on: SL-009 · Closes: — (no `GAP-NNN` yet; R3 audit not run)

## Outcome

A page author writes `<Dropdown id="region" data="orders" valueColumn="region" title="Region" />` or `<MultiSelect id="channel" data="channel_mix" valueColumn="channel" />`; a reader picks option(s) — type-to-search narrows the list — and every widget declaring `filters=["region"]`/`filters=["channel"]` re-queries. The selection serializes to the URL and a reload or shared link restores it.

## Demo

1. Cold start: `bin/biac dev`, open `http://localhost:5173/weekly-review` — a "Region" dropdown renders under the intro Callout, all widgets unfiltered.
2. Open the dropdown, pick **West** — every widget declaring `filters=["region"]` re-queries West-only; the URL shows `?region=West`.
3. Reload — the dropdown shows West selected and the widgets stay filtered (URL read at filter construction).
4. Open the dropdown and type `no` — the option list narrows to **North**.
5. Clear — the `region` param disappears; full-quarter data returns.
6. Open `http://localhost:5173/nested/allocation` — a "Channel" multi-select and a live `<Table>` render; pick **Direct** and **Marketplace** — chips appear in the trigger, the URL shows `?channel=["Direct","Marketplace"]`, and the table narrows to two rows.
7. Reload — the two chips and the narrowed table persist.

**Disagreements named:**

- **Default selection** — streamlit `index=0` and framework `Inputs.select` preselect the first option; mosaic prepends an "All" row so the default is explicit-but-empty; evidence selects nothing unless `select_first`/`initial_value`/URL. This slice decides (below).
- **Option source** — evidence runs bespoke option SQL (server-side dedup/search/limit, plus a second selected-values query); mosaic `SELECT DISTINCT … ORDER BY`; our SL-009 machinery already runs the fence and can derive options client-side. This slice decides (below).
- **Search semantics** — evidence filters by substring (`includes`, server-side `ILIKE` + client filter); streamlit defaults `filter_mode="fuzzy"`. This slice decides (below).
- **One tag or two** — evidence ships one `dropdown` component with `multiple`; streamlit/framework ship distinct `selectbox`/`multiselect` and `select(multiple)`. Our backlog and `docs/research/widget-catalog.md` name `<Dropdown>` and `<MultiSelect>` — two tags sharing one core, matching evidence's single-implementation shape under the catalog's authored surface.

## Deviations

- **Client-side option derivation** over `useFilteredQueryRows` instead of evidence's bespoke options SQL (no `GROUP BY`/`ILIKE`/`LIMIT 10000`/selected-values query); the fence author controls ordering and breadth. If high-cardinality columns ever demand it, evidence's `Dropdown.svelte` query pair is the fallback shape.
- **camelCase props** (`valueColumn`, `labelColumn`, `initialValue`, `selectFirst`, `defaultTopN`) matching our MDX convention (`pageSize`, `deltaFmt`); evidence's snake_case names map 1:1.
- **Cleared state never snaps back** — the `selectFirst`/`defaultTopN` effect guards on `value === undefined`, so a cleared `""`/`[]` stays cleared; evidence's truthiness guard re-fires `setDefault` on a cleared single-select (`FILTER_SYSTEM.md` § Known Issues) and SL-009 already chose `!== undefined` for `initialValue`.
- **No legacy `"`-quoted deserialize** — evidence's branch exists for its old URLs; ours start at this slice.
- **No `<Option>` children, `order`/`where`/`dateRange`, `icon`/`info*`, `maxSelections`, `acceptNewOptions`, `filterMode`, `fmt`** — v1 omits; the deferred pieces are listed under Out of scope.
- **No `{{id.selected}}`-style template values** — `interpolate.ts` rejects `{{inputs.x}}` by design (SL-009 Out of scope); that surface is a later slice's decision.
