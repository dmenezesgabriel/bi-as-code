# SL-048 — A project sets its brand colours, chart palette and heatmap scale, and a page overrides them

Milestone: Phase 4 — Project and page settings, themes, layouts · State: open · Depends on: SL-047 · Closes: GAP-042, GAP-043

## Outcome

An author writes `brand: { colors: { primary, background }, palette, scale }` in `biac.config.ts`, each with `light` and `dark` hex values, and the chrome, input widgets, charts and heatmaps take those colours in both modes. A colour below its WCAG 2.2 contrast floor is a located error that fails `biac build`. The same `brand:` key in one page's front-matter overrides the project for that page only. Today every colour is fixed in `src/web/src/styles.css`, and a project cannot change one without editing the SPA.

## Demo

1. Cold start: `bin/biac dev` at 1440px. On `/orders-dashboard`, `eval` shows `--primary` `#171717` light / `#e5e5e5` dark, `--background` `#ffffff` / `#0a0a0a`, and `--chart-1` `#0072b2` in both modes. The first bar series is Okabe-Ito blue. The `/weekly-review` heatmap ramps from the background to `--chart-1`.
2. Add `brand: { colors: { primary: { light: "#154886", dark: "#60a5fa" }, background: { light: "#fffdf5", dark: "#0a0a0a" } } }` to `biac.config.ts` and save. The tab reloads by itself. The page surface is `#fffdf5`, and the `/weekly-review` checked toggle and the selected button-group item fill `#154886`. Switch to dark: the toggle fills `#60a5fa`. The heatmap ramp starts at `--background`. Change the light background to `#fdf6e3`: the overlay names `brand.colors.background.light`, `--chart-4 #cc79a7`, `2.83:1` and `3:1 (WCAG 2.2 SC 1.4.11)` at `biac.config.ts:<line>:<column>` — the default palette has no headroom on a non-white light background (`--chart-4` is 3.06:1 on `#ffffff`).
3. Add `palette: { light: ["#1e40af"], dark: ["#60a5fa"] }`. Series 1 takes the brand colour, and series 2…8 keep the defaults (open decision O1).
4. Add `scale: { light: ["#1e40af"], dark: ["#60a5fa"] }`. The `/weekly-review` heatmap ramps from `--background` to the brand colour. A widget's own `colorScale` prop still wins.
5. Change the light palette entry to `"#45a1bf"` (2.956:1 on white, printed truncated as `2.95:1`). The overlay names `brand.palette.light[0]`, the measured ratio, the colour it was measured against and the floor `3:1 (WCAG 2.2 SC 1.4.11)`, located at `biac.config.ts:<line>:<column>`. Restore it and the page comes back by itself.
6. The example page added in T5 sets a front-matter `brand:` with a different primary. Only that page uses it; going back to `/` restores the project brand without a reload, and the charts on each page draw that page's palette.
7. `bin/biac build` + `bin/biac preview`: the same colours, with no frame painted in the default colours before the brand ones (ADR-0014's first-paint driver). A failing colour makes `bin/biac build` exit non-zero with the same message.
8. Reload — the effect persists.

**Disagreements the slice settles:** (1) A partial palette: evidence overlays it by position over the defaults, while streamlit replaces the list and cycles it. (2) Scale length: evidence takes 1 or more (one colour is anchored on the background), while streamlit requires exactly 10. (3) Bad colours: evidence drops the override, and streamlit skips the colour with a warning. Ours fails, located. (4) Contrast: evidence derives neighbours by luminance and never measures, and streamlit takes colours as given. (5) Page override: evidence deep-merges per mode, framework swaps whole theme files, and streamlit has none.

## Deviations

- Contrast is measured and enforced at config load. evidence derives and streamlit trusts. The ADR in T5 records why; the check itself carries a comment citing WCAG 2.2 1.4.3 and 1.4.11.
- Only `#RRGGBB` is accepted. streamlit takes any CSS colour, but zrender cannot parse `oklch()` and ADR-0014 keeps every token hex.
- A palette is at most 8 colours. ADR-0016: past 8, ECharts repeats the list, and every extra colour lowers the floor. A 9th entry is an error, not a silent truncation.

## Open decisions

- **O1 — settled in T2 by the author on 2026-10-18: positional overlay**, as in evidence's `overlayColorList`. `palette: { light: ["#1e40af"] }` changes series 1 only, and ADR-0016's tuned defaults keep series 2…8. Each mode is optional and independent; an omitted mode keeps its defaults (`src/engine/brand-css.ts` `modeDeclarations`, `src/engine/types.ts` `BrandTheme.palette`).
- **O2 — settled in T2 by the author on 2026-10-18: unenforced**, recorded in the T5 ADR — the ΔE ≥ 16 guarantee covers the default palette only; the 3:1 floors stay errors. Measured with `test/lib/palette-separability.ts` `minimumSeparation`: evidence's example palette `#154886 #45a1bf #a5cdee #8dacbf #85c7c6` reaches min ΔE 9.6 protan / 9.1 deutan / 9.5 tritan (14.0 normal); the demo's one-colour overlay `#1e40af` over the light defaults drops to ΔE 2.8 protan and deutan against `--chart-7 #4433aa`, so enforcing it would fail demo step 3.
- **O3 — settled in T1** (`src/engine/brand-contrast.ts` `CONTRAST_PAIRS`; extra pairs chosen by the author on 2026-10-18). A pair is checked when either side is a brand colour; the error names the brand side(s) to change, never adjusts the colour.
  - `--primary` vs `--primary-foreground` 4.5:1 (1.4.3) — `button-group.tsx` pressed text, `toggle.tsx` thumb.
  - `--primary` vs `--background` 3:1 (1.4.11) — checked toggle track, `slider.tsx` thumb border.
  - `--primary` vs `--secondary` 3:1 (1.4.11) — `slider.tsx` indicator on its `bg-secondary` track.
  - `--background` vs `--foreground` and `--muted-foreground` 4.5:1 (1.4.3).
  - `--background` vs `--ring` 3:1 (2.4.13), the floor `test/e2e-browser/focus-ring.spec.ts` holds.
  - `--background` vs `--chart-1`…`--chart-8` 3:1 (1.4.11, ADR-0016), and each series vs `--chart-label-inside` 3:1 — a brand palette entry takes its series token's place (T2).
  - Each `scale` colour unchecked, since a heatmap cell's value is in its tooltip and label.

- **O4 — settled in T4 by the author on 2026-10-18 (decide on evidence): the page renders its own `<style>`, and the page body waits for it.** evidence emits the page's theme `<style>` from the page component, unscoped and after the layout's, so it wins by cascade and is torn down on client navigation (`evidence/cli/src/routes/[...path]/+page.svelte`). Its charts read the theme from a Svelte context instead (`setThemeContext`), which ADR-0014 rejected for us. framework has a stylesheet per page HTML document, and streamlit and mosaic have no page override. Ours: `src/web/src/features/pages/page-brand-style.tsx` `PageBrandStyle` renders a plain `<style>` (it stays inside `#root`, after the project's `body-prepend` style) and renders the page body only after its `useLayoutEffect` commits. React flushes that re-render before paint. `page-router.tsx` keys it on `brandCss`, so an edited front-matter brand remounts the page. Measured in `page-router.unit.test.tsx` with a body that reads `--primary` once on mount, as `useChartTokens` does: dropping the gate fails branded→unbranded navigation and the hot swap, and dropping the key fails the hot swap. Known limit: on a cold load straight onto an overridden page, the chrome paints in the project brand while the lazy page module loads (evidence avoids this with SSR; we have no per-page HTML).
- **O5 — settled in T4 by the author on 2026-10-18 (decide on evidence): key by key, as in evidence's `resolveThemeOverrides`.** The page's `brandCss` holds only the keys the page sets, so the cascade is the merge: `colors.primary` alone overrides `--primary`, a palette overlays the project's by position (evidence's `overlayColorList`), and each mode is independent. There are two deviations. `scale` replaces rather than overlays, because one stop means "ramp from `--background`" (O7). A colour still needs both modes, because the front-matter runs `readBrand` (`src/engine/page-brand-frontmatter.ts` `pageBrand`). Contrast is checked on the merged result: `src/engine/brand-contrast.ts` `brandedThemeTokens(projectBrand)` is the theme the page's colours are measured against, and the error names only front-matter keys and the file.
- **O7 — settled in T3 by the author on 2026-10-18: scale length 1 or more**, as evidence takes it (streamlit's exactly-10 is rejected). One colour ramps from `--background`, two or more are the ramp as written. The token is one comma-separated `--chart-scale` per mode, like Tailwind's `--tw-gradient-stops`. Its default is the literal `#0072b2` per mode in `styles.css`, not `var(--chart-1)`, for two reasons. First, evidence (`evidence/core/src/constants/default-theme.ts` `colorScales.default`) and streamlit (`streamlit/frontend/lib/src/theme/getColors.ts` `defaultSequentialColors`) keep the sequential scale as its own literal colours. Second, jsdom leaves `var()` unsubstituted in a custom property's computed value, so `use-chart-tokens.unit.test.tsx` reads `"var(--chart-1)"`. As a result, a brand palette no longer moves the default heatmap ramp.
- **O6 — settled in T1:** `src/engine/contrast-ratio.ts` (`contrastRatio`, `toLinearSrgb`); `test/lib/palette-separability.ts` and `test/lib/series-palette.unit.test.ts` import it.
