# SL-001 — `biac dev`: vite + pages plugin serves the SPA over `pages/**/*.md`

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: — · Closes: —

## Outcome

A user runs `biac dev` in a project directory and gets a dev server where every `pages/**/*.md` file is a route: markdown compiles to React via MDX (front-matter, gfm, shiki-highlighted fences, ` ```sql name ` blocks extracted into the page manifest), and editing a `.md` file hot-reloads the browser.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root (which contains the `pages/` example project), open `http://localhost:5175/`.
2. `/` renders `pages/index.md`: front-matter title in the document title, prose, a gfm table, a highlighted ```sql fence.
3. Follow a markdown link to the second example page (e.g. `pages/nested/page.md` → `/nested/page`) — client-side navigation, no reload.
4. Edit `pages/index.md` in an editor, save — the page updates without a manual reload; add `pages/new-page.md` and navigate to `/new-page` without restarting the server.
5. Open `/no-such-page` — a styled 404 renders.
6. `Ctrl-C` — the server shuts down cleanly.

Where the references disagree, and what that forces us to decide:

- **Compile model.** evidence compiles server-side per request and ships a serialized tree (content lives outside vite's module graph — hence the poll-based reload). framework compiles server-side to an HTML string and hydrates JS islands over a per-page WebSocket diff protocol. Our architecture (`docs/architecture.md` §4, `docs/architecture/building-blocks.md`) is a third model: **MDX → JS module inside vite's module graph**, so HMR is native and neither the poll nor the diff-WS machinery exists. That divergence is the slice's defining design decision — adopted, not open.
- **Unnamed ` ```sql ` fence semantics.** evidence renders a sql fence as a code block (a named fence registers a query); framework's default renders an interactive table. Census flags this for SL-003. SL-001 only extracts ` ```sql name ` blocks into the page manifest and renders the fence as highlighted code — no execution.
- **Home-page convention.** evidence: `home.md` → `index.md` → `README.md` precedence at the pages root. framework: `index.md` only. Ours: `index.md`/`index.mdx` only — one convention.
- **Route surface.** framework ships `[param]` dynamic segments, `.html` normalization redirects, and page loaders (`*.md.<interpreter>`). evidence ships `{slug}/index.md` nesting only. Ours: static paths + `index` convention; the rest is out of scope below.

## Deviations

- No server-side page render: pages compile to JS modules and render in the SPA. SSR is permanently out (ADR-0005 architecture has no runtime backend; `biac build` emits a static SPA).
- No poll endpoint, no reload WebSocket, no diff protocol — vite's watcher + HMR replaces all three because `.md` files are in the module graph.
- Front-matter invalid YAML: framework warns and continues with empty data; ours fails the module compile (vite surfaces it in the overlay) — a broken page should be loud to its author.
- `home.md`/`README.md` home precedence (evidence) not adopted: `index` only.

## Open decisions

- **Compile-error surface for a page that parses but fails at runtime** (e.g. MDX expression referencing an undefined identifier): vite overlay vs in-page error component — decide while building the page renderer; both are cheap, pick whichever reads better in the demo.
- **`handleHotUpdate` semantics for add/remove/rename of `.md` files** — whether invalidating `virtual:biac-pages` alone suffices or routes need explicit rebuild signalling in the SPA. Settle in the plugin task; document the answer here.
