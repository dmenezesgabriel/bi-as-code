# SL-052 — A reader searches every page from the sidebar and jumps to a match with the keyboard

Milestone: Phase 5 — Query files, translations, search · State: open · Depends on: — · Closes: GAP-051

> Delete this file when the slice ships. Every path below was verified on disk on 2026-10-21 (`test -e`); paths marked **new** do not exist yet. Site search is framework-only: by the census rule it is an invention, justified by the owner's request (2026-10-17, `docs/backlog.md` Phase 5) and by the Phase 8 documentation site, which needs it (`docs/research/content-features.md`).

## Outcome

A reader types a word into a search box at the top of the sidebar and sees every page whose title, text or front-matter `keywords` match, ranked, then picks one with the arrow keys and Enter (or a click) and lands on it; a page with `index: false` never shows up.

## Demo

1. Cold start: `bin/biac dev`, open `/`. The sidebar shows a search box under the site title, above the page links.
2. Type `fulfilment` (a body-only word, in `pages/nested/allocation.md` alone): the page links give way to a result list, "1 result", naming Allocation. Clear the box: the page links return.
3. Type `weekly`: "2 results" or more, Weekly review and Weekly orders among them, titles ranked above body-only matches. Press ArrowDown then Enter: the app navigates to the highlighted page.
4. Type a misspelling one letter off (`fulfilmant`): Allocation still matches (fuzzy). Type `fulfil`: it matches too (prefix).
5. Press `/` with nothing focused, or ⌘K / Ctrl-K: the box is focused with its text selected. At 390 px the drawer opens first, then the box is focused.
6. Add `keywords: margin, allocation` to a page's front-matter and save: typing `margin` finds it with no restart. Add `index: false` to `pages/crossfilter-scale.md` and save: typing `scale` no longer lists it, while its sidebar link stays.
7. Open `/weekly-review?lang=fr`: typing `hebdomadaire` (its `fr` `h1`, `translations.yaml`) finds Weekly review. Open `/weekly-review?lang=en`: `hebdomadaire` finds nothing.
8. `bin/biac build && bin/biac preview`: steps 2–5 behave the same; the index arrives as its own chunk on first focus (Network panel), not with the first paint.
9. `console` stays clean throughout.

## Trade-offs and what we adopt

| Axis                  | Options seen (repo → approach)                                                                          | Trade-off                                                                                                                    | Our choice, and why                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| On by default?        | framework → off until `search: true`                                                                    | Opt-in hides the feature from small projects; always-on adds a box to every sidebar                                          | On whenever the sidebar is on: our sidebar already exists for navigation, and the index loads only on first focus, so a project that never searches pays nothing but the box |
| Ranking               | framework → MiniSearch BM25, title and keywords ×4, `fuzzy: 0.15`, `prefix: true`                       | Matching those numbers needs MiniSearch or a re-implementation of its scoring                                                | framework's numbers, through whichever engine O1 settles                                                                                                                     |
| Term processing       | framework → drop terms with more than 6 digits, truncate to 15 characters, NFD-fold accents, lower-case | Truncation keeps the index small; folding lets `region` match `régión`                                                       | Port as-is, written once and used by both index and query (O2 decides where that one place is)                                                                               |
| Result list semantics | framework → `<ol>` of links with a class on the active one                                              | No `role="listbox"`/`option`, no `aria-activedescendant`, no live count — fails what WAI-ARIA APG's combobox pattern expects | A WAI-ARIA combobox (O5), exceeding the reference; the count in a polite live region as `<Search>`'s `<output>` already does                                                 |
| Freshness in dev      | framework → rebuild at most every 10 minutes                                                            | A stale index in dev contradicts ADR-0009 (page edits hot-update)                                                            | Rebuild when a page changes, through the same HMR path as the manifest                                                                                                       |

## Deviations

- No 10-minute reindex cache: a page edit rebuilds the index through HMR, as every other page-derived module does (ADR-0009).
- No `search.index()` config hook for external results: no project of ours links outside itself yet. A future need would add it as `biac.config.ts` `search.extra`.
- No `index: true` for unlisted pages: every discovered page is in the nav (`src/engine/discover-pages.ts`), so there are no unlisted pages to opt in.
- On whenever the sidebar is on, rather than behind a `search: true` flag (see Trade-offs).

## Open decisions

| Id  | Decision                 | Evidence and recommendation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| O1  | Search engine            | framework uses MiniSearch (`framework/package.json` `minisearch`); `npm view minisearch` on 2026-10-21: `7.2.0`, MIT, 0 dependencies, 826,513 bytes unpacked, last modified 2025-09-16 — older than `minimumReleaseAge: 1440` (`pnpm-workspace.yaml`). A hand-written index would have to re-derive BM25, prefix and fuzzy matching. Recommend MiniSearch, pinned exact, behind one wrap site enforced in `.dependency-cruiser.cjs`.                                                                                                                                                                                                                          |
| O2  | Where the index is built | framework builds and serialises it in node (`index.toJSON()`) and the client calls `loadJS` with matching options. Ours cannot share code across the boundary: `.dependency-cruiser.cjs` forbids `src/engine/` → `src/web/` and back, so building in the engine means two MiniSearch wrap sites and duplicated term options. Alternative: the engine ships the plain documents (`{route, title, text, keywords}`) and the browser builds the index on first focus. Measure: index-build time in the browser for the example project (19,411 bytes of pages today) and for a 200-page synthetic set; recommend browser-side unless 200 pages take over 100 ms. |
| O3  | Delivery                 | framework fetches a JSON file it writes into the build. Ours can serve a virtual module (`virtual:biac-search` **new**) that the box imports dynamically: vite emits it as its own chunk in `biac build` (ADR-0008, nothing to copy) and HMR invalidates it in dev. Recommend the virtual module.                                                                                                                                                                                                                                                                                                                                                             |
| O4  | What text is indexed     | framework indexes rendered HTML, code blocks included. Ours never renders to HTML in node; the text comes from mdast. Exclude fenced code (SQL is not page prose) and widget JSX elements (they render data, which framework also skips); keep text inside layout JSX children. `{$translations.key}` in text resolves per language from `resolve-translations.ts` — without it `/weekly-review`'s `h1` and `h2`s index as nothing.                                                                                                                                                                                                                           |
| O5  | Language                 | One document set per declared language, each with that language's resolved text, and the box searches the reader's current language (`resolveLanguage`), so results match what the page will show. The cheaper alternative — index only the first declared language — finds nothing for a French reader typing French. Recommend per language; a project without `translations.yaml` has one set.                                                                                                                                                                                                                                                             |
| O6  | Combobox primitive       | Base UI `Autocomplete` (`src/web/node_modules/@base-ui/react/autocomplete`) gives `role="combobox"`, `listbox`/`option`, `aria-activedescendant` and arrow-key handling; wrap it as `src/web/src/components/autocomplete.tsx` (**new**) beside `combobox.tsx`. framework's hand-rolled list has none of that. Check before choosing: Base UI renders its popup in a portal, while framework replaces the sidebar's page list in place — pick the one whose 390 px drawer layout measures cleaner.                                                                                                                                                             |

## Out of scope

- Indexing query results, table rows or chart data — framework skips them too; a data search is `<Search>` (SL-049).
- Result excerpts and highlighted matches — framework shows titles only.
- External results through a config hook (see Deviations).
- A dedicated `/search` route.
