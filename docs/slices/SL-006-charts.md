# SL-006 — `<BarChart>`/`<LineChart>`/`<AreaChart>`: ECharts wrapper, series, stacking, labels

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-005 · Closes: —

## Outcome

A page author writes `<LineChart data="weekly_trend" x="week" y="orders" series="region" />` and gets an interactive chart — axis tooltip, legend, light/dark themed — bound to the named ```sql fence's materialized rows. `<BarChart>`and`<AreaChart>` share the same prop surface (`data`/`x`/`y`/`series`/`stacked`/`labels`/`xFmt`/`yFmt`/`title`/`height`/`legend`); `stacked`takes`true`/`false`/`"100%"`, `labels`draws per-point values,`y` accepts a column name or an array of column names. No tag issues its own query — every chart reads the page's query registry.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root, open `http://localhost:5175/weekly-review`.
2. "Regional split" shows `<BarChart data="orders" x="region" y="revenue" labels />`: three labeled bars (North/South/West), axis tooltip on hover, `aria-label` on the chart container.
3. "Trend lines" shows `<LineChart data="weekly_trend" x="week" y="orders" series="region" />`: three named lines, a legend, tooltips listing all regions at a week.
4. Below it `<AreaChart data="weekly_trend" x="week" y="orders" series="region" stacked="100%" />` renders the same fence as normalized stacked area (y reads 0–100%).
5. Click the theme toggle — charts repaint in the dark palette without a reload; click back.
6. Open `http://localhost:5175/weekly-review?region=Atlantis` — every chart bound to a filtered-empty fence renders its empty state, not an error.
7. Point one chart's `data` at an undeclared name — inline `role=alert` names it; `x`/`y`/`series` typos name the column and list the available ones. Revert.
8. `console` stays clean throughout; no worker post fires after results settle (charts are registry reads).

## Deviations

- **No SQL-generating props** — evidence's `build-chart-sql.ts`, `metric=`, `date_grain`, `filters`/`where`/`order`/`limit`, `x_sort`, `axisHasAggregation` are unported; the fence owns SQL (SL-005 precedent). `x`/`y`/`series`/`labels` name columns, not expressions.
- **No `y2`/dual axis, no combo children, no `<line>`/`<bar>` child composition** — `ComboChart.svelte`/`MultiSeries.svelte`/`allowedChildren` machinery unported; three standalone tags, `y={["a","b"]}` covers the multi-series need without a y2 axis.
- **No `echarts_options`/`echarts_series_options`/`chart_options` escape hatches** — raw option merge props wait for a demonstrated need; `<CustomEchart>`-style raw spec is a later row in `docs/research/widget-catalog.md`.
- **No print mode, copy-as-image, connect-group, touch-dismiss, axis-label thinning/rotation machinery** — the bulk of `echarts.action.ts`/`echarts-utils.ts` (`withAutoXAxisLabelLayout`, `withMeasuredTimeAxisLabelThinning`, extra-height negotiation) is print/mobile/label-density polish; v1 relies on echarts' built-in `axisLabel` handling.
- **No `fillGaps`/`handle_missing`** — stacked series align on the union of x values with missing points emitted as gaps (echarts renders nulls); evidence's `connect`/`zero`/`gaps` option set is deferred.
- **No `tooltip_fields`/`point_title`** — the tooltip is the axis default with `yFmt` formatting; extra fields are an additive prop later.
- **DOM custom legend deferred** — `CustomLegend.svelte` exists because canvas legends aren't reachable; v1 uses echarts' legend plus `aria` description; SL-014 revisits when legend toggles become selection clauses.
- **Sparkline stays hand-rolled SVG** — the inline span can't host an echarts instance (block layout + engine weight); the SL-005 "may delegate" note resolves to _doesn't_.
- **`height` is pixels only** — no percent/`content` auto-height (streamlit's `height="content"` needs aspect machinery); default ~300px.

## Open decisions

- **jsdom seam for widget tests** — RESOLVED in T1: `echarts.init(el, null, {renderer:"svg"})` renders real svg under jsdom (`getContext` stub returns null; canvas is out). Tests and stories pass `renderer="svg"`; no injected init needed — the fallback remains available if a later need (e.g. canvas-only assertions) demands it.
- **X-axis type inference** — RESOLVED in T2: `inferXType` reads the first non-null x cell — `Date`→`time`, `number`/`bigint`→`category` for bar / `value` for line+area, everything else→`category`. Category numerics are stringified (ECharts would read them as ordinals); `Date` domain slots dedupe by instant. Unit tests cover bigint cells.
- **`labels` position/format defaults** — RESOLVED in T3: flat `labels`/`labelsFmt` props; position `top` for line/area and unstacked bar, `inside` for stacked bar (a top label on a stack reads as the total); format `labelsFmt` wins, else `pct0` on `"100%"` stacks, else `yFmt`; `labelLayout.hideOverlap` always on.
- **Theme context shape** — RESOLVED in T1: `ThemeModeProvider`/`useThemeMode` live in `src/web/src/features/chrome/theme-mode.tsx`; `App.tsx` wraps **both** render branches, so `nav.sidebar:false` projects carry the mode too.
