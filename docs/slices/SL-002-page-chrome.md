# SL-002 — Page chrome: sidebar nav, ToC, breadcrumbs, theme, `biac.config.ts`

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-001 · Closes: —

## Outcome

A user running `biac dev` sees real app chrome instead of a bare page: a sidebar nav tree built from `pages/` (labels and order from front-matter), a per-page table of contents with scroll-spy, route-derived breadcrumbs, a light/dark theme toggle persisted per browser, and a `biac.config.ts` project config carrying `title`/`theme`/`nav`.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root, open `http://localhost:5175/`.
2. Sidebar lists `pages/` as a tree: `pages/index.md` first, `pages/nested/page.md` under a "Nested" group; the active route is highlighted.
3. Open a page with several `##`/`###` headings — a ToC on the right lists them and the current section highlights while scrolling.
4. Breadcrumbs above the article read `Home / Nested / <page title>` on `/nested/page`; on `/` only the home crumb renders.
5. Click the theme toggle — the UI inverts to dark; reload — it stays dark; a fresh browser profile falls back to `prefers-color-scheme`.
6. Edit `biac.config.ts` in the project root (set `title: "ACME"`) — the app reloads and the sidebar header + untitled-page document title read "ACME".
7. Set `nav: { sidebar: false }` in the config — the sidebar disappears and content spans the viewport.

## Deviations

- **Breadcrumbs are an invention** — no reference implements them in chrome. Scope is deliberately minimal: crumbs = `Home` / directory segment(s) / page title, all from the route. If it grows requirements (e.g. custom crumb labels), it moves to a later slice.
- **Config is a TS module, not YAML/TOML** — `biac.config.ts` is backlog-fixed; `loadConfigFromFile` executes it like vite executes `vite.config.ts` (same trust model — local project code).
- **Theme application is client-side only** — no SSR, so no cookie-driven first paint like evidence's sidebar width; an inline head script in `index.html` applies the persisted/system choice before React mounts (FOUC guard).
- **ToC reads the rendered DOM, not the AST** — both references generate heading anchors client-side (evidence slugs them on mount; framework relies on markdown-it heading ids). Our MDX output needs stable heading ids: add them at render-time from the ToC component (evidence's approach — no rehype plugin needed).
- **No named theme palettes** — evidence `theme.yaml`/framework `air`/`near-midnight` are token systems; v1 is light/dark only. `theme` in config means the default mode, not a palette name.
- **Front-matter `icon` not adopted** — needs an icon set and a wrap site; deferred (evidence uses lucide — the same library the theme toggle will install, so a later slice can add it cheaply).
- **No sidebar width handle / no search box / no pager links** — evidence cookie width, framework `search:`/`pager`, all deferred.

## Open decisions

- ~~**Sidebar collapse persistence granularity** — framework persists each section's open state keyed by its summary text (fragile to renames, but proven); evidence keeps it in-memory.~~ **Settled in T3:** sessionStorage JSON map (`biac.sidebar.dirs`) keyed by `dir.id` — framework's persistence with a stable slug key that fixes the rename fragility; runtime semantics follow evidence — a stored explicit choice wins over contains-active (including for the active dir), unstored dirs open iff they contain the active page.
- **Sidebar toggle model (settled in T3)** — dual state: desktop show/hide is a persisted explicit override (`biac.sidebar.open`; absent = auto-visible); mobile (<lg, 1024px) is an ephemeral overlay drawer closed by link click, backdrop or Escape. Breakpoint `lg` chosen over evidence's 768px because framework's `calc(640+96+272)`≈1008px formula guarantees ≥640px of content — `lg` (1024px) is the nearest Tailwind step. The framework `⌘B`/`Alt-B` shortcut and focus-trap drawer polish stay deferred.
- **ToC when zero headings** — framework emits an empty `<aside>`; collapsing to nothing shifts layout. Decide render-vs-absent in the ToC task (leaning: render nothing under 2 headings).
- **`biac.config.ts` reload while the dev server runs** — invalidating the virtual module full-reloads (loses SPA state incl. scroll). Acceptable for v1; a config-aware HMR boundary is revisit-only.
