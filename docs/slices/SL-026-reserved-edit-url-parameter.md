# SL-026 — A page cannot take the editor's `edit` URL parameter for itself

Milestone: Phase 1 — Known debt · State: open · Depends on: — · Closes: the Known-debt "`edit` is a reserved URL parameter" row in `docs/backlog.md` (no `GAP-NNN`; the row postdates the usability audit)

## Outcome

An author who names a filter `edit` is told so at the line that does it, instead of getting an input that opens the source editor when used; and a page's SQL never sees the editor's own `?edit` flag as `{{params.edit}}`.

## Demo

A numbered script a human runs from a cold start. Steps 2–6 edit `pages/index.md` through the editor; step 7 restores it.

1. Cold start: `pnpm build:cli && bin/biac dev`, open `http://localhost:<port>/weekly-review?edit=West`. Before this slice the source editor opens (measured: 1 `.cm-editor`). After: decided by Open decision 4 — record which.
2. Open `/?edit=true`. In the editor add a line `<TextInput id="edit" title="Edit" />` and save (`Mod-s`).
3. The preview pane shows the compile-error page naming `pages/index.md`, the line and column of the tag, the id `edit` and that it is reserved for the source editor. The editor stays open and editable (no vite overlay, no full reload).
4. Change the line to `<Table data="orders" filters="edit" />` (`orders` is the page's named fence) and save: the same error, pointing at the `filters` attribute.
5. Replace the line with a fence ` ```sql leak display ` / `select {{params.edit}} as leaked` / ` ``` ` and save: the result table shows `leaked` as NULL while the URL holds `?edit=true`. Before this slice it bound the parsed flag (`true`, seen on screen in T1's RED run).
6. Click `Done`, then `Edit`: `leaked` reads NULL on both sides of each click. Every fence on the page still re-queries on both clicks — the page remounts as it moves in and out of the editor's preview pane (`src/web/src/features/pages/editable-page.tsx`), measured at 103 duckdb worker posts per click on `/weekly-review` before and after T1 — so the re-query is not something this slice removes; what T1 removes is the `params` change itself (`src/web/src/features/pages/markdown-page.unit.test.tsx`: 2 queries → 1 when only `edit` leaves the URL).
7. Remove the fence, save, `Done`; `git diff -- pages/` is empty.
8. Put the `<TextInput id="edit" />` line back in `pages/index.md` on disk, run `bin/biac build`: the build fails with the same message and location. Remove the line; `bin/biac build` passes and `bin/biac preview` → `/weekly-review?region=West` still filters.
9. Console stays clean on every step except the compile error under test.

## Deviations

- Streamlit matches reserved keys case-insensitively; we match exactly, because our router and `isEditSearch` do. Stated in a comment at the reserved-key definition.
- Streamlit raises at runtime; we raise at compile time for what the compiler can read. If Open decision 1 adds a runtime guard, that is the streamlit shape and no deviation.

## Open decisions

Each has a recommendation; the task that implements it settles it, and the outcome goes into ADR-0010 (Open decision 5).

1. **Non-literal ids.** `id={expr}` and `filters={expr}` cannot be read by a remark visitor, and v1 pages are string refs only (Known debt: `MDX` expression refs unsupported — but `filters={["region", "amount"]}` array literals are in `pages/weekly-review.md` today and must be read). Options: (a) compile check only, reading string and array-of-string literals, anything else passes; (b) also throw in `src/web/src/features/filters/filters.ts` `ensure`, the one runtime chokepoint. A third path needs neither: a chart selection is keyed by its column name (`use-chart-publish.ts`), so a column called `edit` reaches `selection("edit")` with no id in the source. Throwing there would reject valid data. T3 must first measure whether a selection-only filter (never bound to an input) reads or writes the URL at all (`src/web/src/features/filters/filter.ts` constructor and `searchParams` call sites); if it does, the fix for that path is that such a filter skips URL persistence for a reserved key, not an error. Recommendation: (a) for author-written ids, (b) only for ids that come from an input's `id` or a `filters` list, and the measured answer for chart fields.
2. **Dev only, or build too.** `biac build` has no editor (ADR-0010), so `edit` collides with nothing there. Recommendation: reject in both — a page that builds but breaks under `biac dev` cannot be authored, and one rule is easier to state.
3. **Where the reserved list lives.** `src/engine/` (node) and `src/web/src/` (browser) share no module today. Options: one constant per side with a test on each (streamlit's shape), or a first shared module both import. Recommendation: one constant per side — a one-element list does not justify a new cross-package edge; revisit when a second reserved key appears.
4. **Should a non-flag value still open the editor.** Today `?edit=West` opens it. Once no filter can write `edit`, narrowing `isEditSearch` is not needed for correctness. Recommendation: leave `isEditSearch` unchanged; demo step 1 records it as unchanged.
5. **ADR.** ADR-0010 line "`edit` is a reserved search parameter in `biac dev`, and nothing enforces it yet…" must become a statement of how it is enforced. Recommendation: edit ADR-0010 in place; no new ADR, the decision is the same one.

## Out of scope

- Duplicate filter ids, empty ids, or ids that are not valid URL keys — a separate validation, not this collision.
- Reserving any key other than `edit`; the list has one member until the product owns a second URL flag.
- `MDX` expression refs (`data={orders}`) — its own Known-debt row.
- Carrying or dropping `edit` across internal page links (evidence's `INTERNAL_PARAMS` concern) — `src/web/src/features/chrome/edit-page-link.tsx` already removes only its own flag on `Done`; cross-page link behaviour is unchanged here.
