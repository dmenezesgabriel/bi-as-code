# SL-036 — One look from one source: semantic theme tokens, one radius scale, one focus ring

Milestone: Phase 2 — A polished UI · State: open · Depends on: — · Closes: GAP-018, GAP-027, GAP-029

> A PRD exists so the executing agent **never guesses and never assumes**. Every path below was checked on disk on 2026-10-15; every number carries the command that produced it.

## Outcome

Every surface, text, border, input, focus ring and chart colour on every page comes from one named token set with a light and a dark value, every corner from one derived radius scale, and every focusable control shows the same visible ring — so changing one token restyles the chrome, every widget and the ECharts theme together.

## Demo

A numbered script a human runs from a cold start. The slice is not `shipped` until this has been run in the real app.

1. `pnpm build:cli && bin/biac dev --port 5536`, open `http://localhost:5536/weekly-review` at 1280×720 in light mode.
2. DevTools → `:root`: `--background`, `--foreground`, `--muted`, `--muted-foreground`, `--border`, `--input`, `--ring`, `--card`, `--chart-1`… and `--radius` are defined; toggle the theme button: `.dark` redefines every colour token.
3. The page looks the same as before the slice in both modes (the token values start equal to today's tones), including the charts' axes, gridlines, tooltips and series colours.
4. In DevTools change `--border` and `--radius` on `:root`: every border and corner on the page changes, the chart gridlines follow `--border` after a theme toggle.
5. Click the page body, press `Tab` 40 times: every stop — sidebar links, header buttons, filter inputs, slider thumbs, `<Details>`, tabs, sort headers, pagers — shows the same ring, at least 2 px, in light and in dark.
6. `/`, `/crossfilter-scale`, `/nested/…`, a 404 path and a page with a compile error: same, both modes.
7. `bin/biac build && bin/biac preview` → `/weekly-review`: same as steps 3 and 5.

Tailwind 4's `neutral-400` (`oklch(0.708 0 0)`) paints `rgb(161,161,161)` = `#a1a1a1`, not Tailwind 3's `#a3a3a3` that `charts/theme.ts` `TOKENS` copies (`textMuted` dark, `axisLine` light) — measured by `test/e2e-browser/theme-tokens.spec.ts`; every other neutral in use matches its v3 hex. `--muted-foreground` dark is `#a1a1a1`; T2's chart theme reads it instead of the stale literal.

ECharts colour parsing: `node_modules/.pnpm/zrender@6.1.0/node_modules/zrender/lib/tool/color.js` `parse` handles hex, named, `rgb(a)` and `hsl(a)` — no `oklch`. Tailwind 4.1.8's palette (every `neutral-*` above) is `oklch`. A token the chart theme reads must therefore be authored in a zrender-parsable format, or be converted before it reaches `registerTheme`.

**Disagreements:**

1. **Source of truth.** evidence and streamlit keep a TS object and emit CSS / feed charts from it; framework keeps CSS vars only and its SVG charts read them. Our chart is a canvas, so CSS-only means reading the vars back at runtime.
2. **Colour format.** evidence's static `base.css` is `oklch`; evidence's emitted CSS is `hsl(hexToHSL(…))`, streamlit and framework are hex. zrender cannot parse `oklch`.
3. **Focus ring mechanism.** evidence `ring-[3px] ring-ring/50` and streamlit `box-shadow` vs `outline` (framework underline; ours today `outline-2`). A `box-shadow` is clipped by `overflow: hidden` ancestors; an `outline` with negative offset is not offset outside the box.
4. **Derived tones.** framework derives every muted tone by `color-mix` from two bases; evidence and streamlit list each token explicitly.

## Deviations

- Hex token values instead of evidence's `oklch`: zrender 6.1.0 does not parse `oklch` (see Evidence). Stated in the ADR the first task writes, and in a comment in `styles.css`.
- No user-configurable themes, no named theme set, no card context: one light and one dark look is the slice.
- Status tones consolidated, so demo step 3 does not hold pixel-for-pixel for them: error states move from red-800 text (light) and red-950/900/300 (dark) to the error callout's family; a red negative `<Value>` moves from red-600 to red-700 (light); delta chip tints wash the 700/400 text hue instead of 600/400; the 404 link's dark tone moves from blue-400 to blue-500, matching the prose link (blue-400 fails 3:1 against the dark body text, WCAG 1.4.1). Measured by `test/e2e-browser/content-tokens.spec.ts`.
