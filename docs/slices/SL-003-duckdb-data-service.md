# SL-003 — DuckDB-WASM data service: `sql:` front-matter, named ` ```sql ` queries, `{{param}}`

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-001, SL-002 · Closes: —

## Outcome

A page author declares data files once — `sql:` front-matter per page or `biac.config.ts` project-wide — writes ` ```sql name ` blocks, and sees each named block execute in the browser via DuckDB-WASM with its Arrow result rendered under the highlighted query; `{{params.x}}` pulls URL search params and `{{other_query}}` composes on a named query's SQL.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root, open `http://localhost:5175/`.
2. `pages/index.md` declares `sql: {orders: data/orders.parquet}` in front-matter; its existing ` ```sql orders ` block renders highlighted SQL plus a live result table (rows match `data/orders.parquet` contents).
3. `pages/weekly-review.md`'s ` ```sql weekly_trend ` block renders its result the same way; a query referencing `{{orders}}` inlines the named query's SQL as a subquery.
4. Open `http://localhost:5175/?region=West` on a page whose SQL contains `{{params.region}}` — the rendered result is filtered to West; remove the param — the unfiltered/baseline behavior the PRD tasks specify applies.
5. Edit `data/orders.parquet`'s registration to a missing file — the block shows an inline error naming the source, not a page crash; console stays clean of unhandled rejections.
6. `biac.config.ts` declares a project-wide `sql:` table — a second page queries it without re-declaring.

## Deviations

- **No DuckDB extensions in v1** — framework's `src/duckdb.ts` manifest/cache machinery (httpfs, spatial, …) is deferred; `registerFileURL` covers local `data/` files without extension loads. If a registered URL ever needs httpfs, a later slice installs the extension machinery.
- **`sql:` sources restricted to `<root>/data/`** — framework resolves any project-relative path through `/_file/`; we trade that freedom for a dev/build-stable `/data/` URL and one directory convention. Stated in a comment at the validation site; becomes an ADR only if challenged.
- **`{{inputs.*}}`/`{{filters.*}}`/`{{"sql-file"}}`/`{{$var}}`/`[[conditional]]`/`| fallback` deferred** to their owning slices (SL-009 filters, SL-017+ templating) — v1 interpolates `{{params.name}}` (URL search params) and `{{query_name}}` (subquery composition, cycle-guarded).
- **Prepared-statement params for `{{params.*}}`** — evidence interpolates text with dialect escaping; we emit `?` placeholders + bound args (framework's `${}` mechanism under evidence's `{{}}` syntax). No string escaping code to get wrong.
- **`streamlit` row is ABSENT by model** — its `st.sql` runs server-side; kept for completeness, not a source of behavior to port.
- **Bundle loading is self-contained** — mosaic's `getJsDelivrBundles`/`importScripts` CDN worker is rejected (offline + supply-chain); vite bundles the wasm module + worker (`?url`/`?worker` imports — exact mechanism settled in T4).

## Open decisions

- **Absent `{{params.name}}` behavior** — empty string vs literal-`NULL` vs error. Recommend: missing param → SQL `NULL` bound arg (predictable, still type-checks in comparisons); settle in T5 with a test.
- **Numeric/typed params** — `{{params.limit}}` bound as string vs parsed number. Recommend: bind the raw string; authors `CAST` explicitly (duckdb coerces `= '5'` comparisons anyway). Confirm in T5.
- **Whether unnamed ` ```sql ` blocks execute** — recommendation: no (code-only, no registry entry); a block must be named to run. Cheap to revisit.
