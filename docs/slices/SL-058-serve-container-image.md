# SL-058 — Run a biac project as a hardened `biac serve` container on AWS

Milestone: Phase 7 — Self-hosting and authentication · State: open · Depends on: SL-057 · Closes: GAP-062

## Outcome

An owner runs `docker build` on a biac project and gets one image. It serves that project's `build/` with `biac serve` as uid 10001 on a read-only root filesystem with every capability dropped, on the port `$PORT` names. A page in `pages/` then tells them how to run that image on ECS/Fargate behind an ALB with basic auth (T1) or behind the ALB's own OIDC sign-in (T2).

## Demo

1. Cold start: `docker build -t biac-serve .` at the repo root. The image bakes the example project: `pages/`, `data/`, `biac.config.ts`.
2. `docker run --rm --read-only --cap-drop ALL --security-opt no-new-privileges:true -p 8080:8080 -e PORT=8080 biac-serve` with no credentials exits `1`. Its message names `BIAC_BASIC_USER`, `BIAC_BASIC_PASSWORD` and `BIAC_AUTH_DISABLED`.
3. The same command with `-e BIAC_BASIC_USER=viewer -e BIAC_BASIC_PASSWORD=s3cret` prints `auth: basic (user viewer)`. `curl -si http://localhost:8080/` returns `401` with `WWW-Authenticate: Basic`, and `curl -si -u viewer:s3cret http://localhost:8080/weekly-review/` returns `200`.
4. `docker exec <id> id -u` prints `10001`. `docker exec <id> sh -c 'touch /app/x'` fails with `Read-only file system`.
5. In a browser with credentials, `http://localhost:8080/weekly-review/` renders its charts. A Search regions entry re-queries the page, and the console has 0 errors.
6. `docker stop <id>` returns in well under the 10 s kill timeout, because `node` is PID 1 through `exec` and handles SIGTERM.
7. In `bin/biac dev`, the deployment guide page in `pages/` renders at 375 px and on desktop with the T1 and T2 sections and the AWS mapping.

## Deviations

- No health endpoint (D-health). The guide matches on `401`. An unauthenticated path would be an invention relative to evidence, and ADR-0030 makes every path authenticated.
- No `HEALTHCHECK` in the Dockerfile: `node:24-slim` has no `curl`, and the orchestrator's check is the ALB's.
- Capabilities, `no-new-privileges` and a read-only root go beyond both references (OWASP rules 3, 4, 8). They are a runtime contract in the guide and in the deploy test, not something a Dockerfile can enforce.
