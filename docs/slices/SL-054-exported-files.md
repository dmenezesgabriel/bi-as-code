# SL-054 — Another site fetches a project's data files by stable URL, typed, from the origins the project allows

Milestone: Phase 6 — Embeds · State: open · Depends on: — · Closes: GAP-055

## Outcome

An author lists the sites allowed to read the project's data in `biac.config.ts`, and a page on one of those origins fetches `/data/orders.parquet`, `/data/orders.csv` or a loader's output such as `/data/weekly-orders.csv` — whole or by byte range — with its real media type, while every other origin is refused by the browser.

## Demo

1. Cold start: `pnpm build:cli && bin/biac dev`. In a scratch directory, write `host.html` whose script runs `fetch("http://localhost:5175/data/orders.csv")`, `fetch("http://localhost:5175/data/orders.parquet", { headers: { Range: "bytes=0-3" } })` and `fetch("http://localhost:5175/data/weekly-orders.csv")`, and writes each status, `Content-Type`, the first line of the CSVs and the four parquet bytes into the page (or the error name when a fetch rejects). Serve it with `python3 -m http.server 8901 --bind 127.0.0.1`.
2. Without any config change, open `http://127.0.0.1:8901/host.html` — all three fetches reject with `TypeError` and the console names the missing `Access-Control-Allow-Origin`. Before this slice they succeed, because vite's own CORS rule admits every loopback origin (Baseline), and the parquet arrives untyped; this step is the observable proof of O3.
3. Add `http://127.0.0.1:8901` to the allowlist O1 settles in `biac.config.ts` and reload the host page — the CSV fetch shows `200`, `text/csv` and the header row; the parquet fetch shows `206`, `application/vnd.apache.parquet` and `PAR1`; the loader output shows `200`, `text/csv` and its header row.
4. Open the same `host.html` from `http://127.0.0.1:8902` (a second `http.server`, not listed) — all three fetches still reject.
5. `curl -sI http://localhost:5175/data/orders.parquet` without an `Origin` — `200`, `Content-Type: application/vnd.apache.parquet`, no `Access-Control-Allow-Origin`.
6. Stop dev, `bin/biac build && bin/biac preview`, repeat steps 3–5 against port 4173 — the same results from the built `build/data/`.
7. Reload the host page — the result persists (the config is the only state).

| `-H 'Range: bytes=0-3'` with `Origin: https://other.example`                                                                       | `206`, `Content-Range: bytes 0-3/3440`, no `Access-Control-Allow-Origin`                                                                       | not measured (GAP-055 records `206` without `Origin`)                            |

What the baseline says: the `Vary: Origin`, the preflight `204` and the localhost `Access-Control-Allow-Origin` all come from vite's own CORS middleware (the `cors` package), which runs ahead of every `biac` middleware in both servers and whose default origin pattern `defaultAllowedOrigins` in `node_modules/vite/dist/node/chunks/node.js` admits only `localhost`, `127.0.0.1` and `[::1]` — for the whole site, pages included. So today every loopback page on any port reads every file, and a public origin reads none: there is no way to list one consumer, nor to refuse a second loopback one. Nothing in `src/` sets a CORS header. vite's preview server answers `.parquet` with an empty `Content-Type`; our dev middleware answers `application/octet-stream`.

## Standards that bind the design

| Fact                                                                                                                                                                                                                                                                                    | Source                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| A `Range` request header is CORS-safelisted when it parses as a single range with a start (`bytes=0-`, `bytes=0-3`); suffix ranges like `bytes=-500` are not, and trigger a preflight                                                                                                   | https://fetch.spec.whatwg.org/#cors-safelisted-request-header (fetched 2026-10-22)                      |
| CORS-safelisted response headers: `Cache-Control`, `Content-Language`, `Content-Length`, `Content-Type`, `Expires`, `Last-Modified`, `Pragma`; any other (`Content-Range`, `Accept-Ranges`, `ETag`) is hidden from the fetching script unless listed in `Access-Control-Expose-Headers` | https://fetch.spec.whatwg.org/#cors-safelisted-response-header-name                                     |
| When `Access-Control-Allow-Origin` is anything but `*` or a static origin, send `Vary: Origin`, or a cached non-CORS response is reused for a CORS request                                                                                                                              | https://fetch.spec.whatwg.org/#cors-protocol-and-http-caches                                            |
| `application/vnd.apache.parquet`, extension `.parquet`, registered by the Apache Parquet Project 2024-02-14                                                                                                                                                                             | https://www.iana.org/assignments/media-types/application/vnd.apache.parquet                             |
| vite's `server.cors` default is `{ origin: /^https?:\/\/(?:(?:[^:]+\.)?localhost                                                                                                                                                                                                        | 127\.0\.0\.1                                                                                            | \[::1\])(?::\d+)?$/ }`; `preview.cors` falls back to it | https://vite.dev/config/server-options#server-cors; `node_modules/vite/dist/node/chunks/node.js` (`cors: preview?.cors ?? server.cors`) |
| The old default `server.cors: true` let any website read a dev server's responses — CVE-2025-24010, fixed in vite 6.0.9                                                                                                                                                                 | https://github.com/vitejs/vite/security/advisories/GHSA-vg6x-rcgg-rjx6                                  |
| DuckDB-WASM 1.32.0's HTTP file system reads only `Content-Length` and `Last-Modified` from responses (both safelisted) and sends `Range: bytes=0-` / `bytes=0-0` (both safelisted) — so a cross-origin DuckDB read needs `Access-Control-Allow-Origin` and no preflight                 | `src/web/node_modules/@duckdb/duckdb-wasm/dist/duckdb-browser-eh.worker.js` (`getResponseHeader` calls) |
| A static build is one SPA folder; whoever serves it sends the headers                                                                                                                                                                                                                   | `docs/adr/0008-static-build-is-a-spa-folder.md`                                                         |
| Every file a page queries is downloadable by its viewer                                                                                                                                                                                                                                 | `docs/adr/0005-queries-run-client-side-in-duckdb-wasm.md`                                               |
| Chromium's Local Network Access checks block a public page from fetching `localhost`; a cross-origin test must use a second loopback origin (`127.0.0.1`)                                                                                                                               | `test/e2e-browser/embed-framing.spec.ts` `serveHostPage`                                                |

## Deviations

| What                                               | Why                                                                                                                                                                                                                                 |

| No explicit export list (framework `dynamicPaths`) | Every `/data/` file is already public to any viewer (ADR-0005) and already published unhashed; a second list would only restate it                                                                                                  |
