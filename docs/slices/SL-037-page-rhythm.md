# SL-037 — Page rhythm: one block gap, SQL fences on their own surface, prose at a readable measure

Milestone: Phase 2 — A polished UI · State: open · Depends on: SL-036 (tokens, `--radius`) · Closes: GAP-019, GAP-020, GAP-028

> A PRD exists so the executing agent **never guesses and never assumes**. Every path below was checked on disk on 2026-10-16; every number carries the probe or command that produced it.

## Outcome

Consecutive blocks on a page (widgets, charts, tables, fences, paragraphs) sit one spacing-scale gap apart instead of touching, a SQL fence reads as code on its own muted, padded, rounded surface in both modes, and a paragraph stops near 70 characters per line on every page, with or without a table of contents.

## Demo

1. `pnpm build:cli && bin/biac dev --port 5537`, open `http://localhost:5537/weekly-review` at 1280×900 in light mode.
2. Scroll the page: no widget, chart, table or fence touches the block above or below it. The KPI row, the charts under _Regional split_, the SQL fence and the table under it are each separated by the same gap.
3. The SQL fence under the _Regional split_ chart sits on a light-grey rounded box with padding, in smaller monospace type than the paragraphs; every syntax colour, the comment included, stays readable on it.
4. Toggle the theme: the fence's box is the page's muted surface (not shiki's blue-black), still rounded and padded; the gaps are unchanged.
5. Open `/` at 1920×900 (no table of contents): paragraphs wrap near 70 characters; the chart and the table still use the full column width.
6. Repeat 2–5 on `/crossfilter-scale` and at 375 px wide: the gaps hold, nothing overflows the viewport, a wide fence scrolls inside itself.
7. `bin/biac build && bin/biac preview` → `/weekly-review`: same as 2–4.

### Where they disagree — the decisions this slice makes

1. **How the block gap is applied:** evidence → one container utility (`*:space-y-block-gap`, margin on every non-first child); streamlit → flex `gap` on the column; framework → per-element `margin: 1rem 0` that collapses.
2. **What the measure caps:** evidence and streamlit → the whole column (65ch / 736px), so charts and tables narrow too; framework → only text elements (640px), charts and tables keep the column.
3. **Syntax colours on the new surface:** evidence and framework → syntax colours are tokens chosen for the surface; streamlit → a fixed prism palette on its own background. We use shiki's github-light/github-dark-default, whose light colours fall under 4.5:1 on any tinted surface (Evidence table above).

## Deviations

- The measure caps text elements only (framework), not the column (evidence, streamlit): a BI page is mostly charts and tables, and a 70ch cap on them would waste the width the ToC-less pages have. State this in a comment beside the cap.
- `ProseParagraph` and `ProseTable` keep a bottom margin (`mb-block-gap last:mb-0`) instead of dropping it: Callout, Details, Accordion and Tab bodies have no column gap and rely on it. Inside `main` it equals the column gap, so the page measures the same.
- The 375 px opened-filter-bar test moved to a 375×667 viewport: without the inputs' `mb-4` the panel's content (352 px) fits the 812 px viewport's half-height cap (362 px), so it no longer exercised the scroll.
- No copy button on fences (evidence, streamlit have one) — not part of any gap this slice closes.

## Open decisions

1. **Syntax colours on `--muted` — settled: (a).** (b)/(c) measured out: github-light comment 4.42 and keyword 4.20 on `#f5f5f5`, and shiki's own `github-light-default` still has `#6e7781` at 4.17. Adopted: `createCssVariablesTheme({ name: "biac-tokens" })` in `shiki-highlighter.ts`; `--shiki-background: var(--muted)` and twelve `--shiki-token-*` values per mode in `styles.css`, GitHub Primer hues picked to pass on `--muted` — light lowest function `#8250df` 4.63, keyword `#cf222e` 4.91, comment `#57606a` 5.86; dark lowest comment `#8b949e` 5.83. The `.dark .shiki` `!important` rule is gone; ADR-0014 carries the outcome. `--shiki-ansi-*` stays undefined (only `ansi` fences emit it). The fence padding sits on shiki's `pre` (`[&>pre]:px-4 [&>pre]:py-3`), which `min-w-fit` grows to the code width, so the right gutter scrolls into view; the `rounded-md` scroller clips its background.
2. **Filter bar under a column gap — settled.** Wrapping sentinel, bar and spacer in one block is out: a sticky element sticks only inside its parent, so docking would end at the wrapper's bottom. Adopted: the sentinel moves by `relative -top-(--dock-top)` instead of `-mt`/`mb` margins (a negative margin collapsed with the block above and ate its gap — the measured 0 px h2/p → bar) and takes `mb-0`, so its flow position is the bar's rest top; the spacer takes `mb-0` so a docked spacer does not open a second gap (measured: `scrollY` 616 instead of 600 without it). Measured sentinel-to-bar offset: master 52 px on `/weekly-review` (the card face fired 12 px before the pin), now 64 px on `/weekly-review` and `/crossfilter-scale`. p → bar 16 px, h2 → bar 12 px (the heading's own margin). `toc-jump.spec.ts` green.
