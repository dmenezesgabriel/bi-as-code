# SL-020 — Edit a page without losing work or hunting for the broken line

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-017 · Closes: GAP-007, GAP-008

## Outcome

An author who leaves the page editor with unsaved changes is asked first, by an in-app link, `Done`, back/forward, reload or tab close. A front-matter YAML error names its file line and column (`pages/weekly-review.md:2:8`), just as a page-body error already does.

## Demo

1. Cold start: `bin/biac dev`, open `http://localhost:<port>/weekly-review?edit`.
2. Type ` zz` at the end of the `# Weekly review` heading line (do not save). The status reads `Unsaved changes`.
3. Click the sidebar link `Orders overview`. A confirm dialog asks to leave with unsaved changes. Cancel. The URL is still `/weekly-review?edit`, the buffer still holds ` zz`, and the status still reads `Unsaved changes`.
4. Move a filter in the preview (Region dropdown → `West`). No dialog appears, and the URL gains `region=West`.
5. Click `Done`, then Cancel → still in the editor. Click `Done`, then OK → `/weekly-review?region=West` with no editor; the file on disk has no ` zz` (`git diff pages/` is empty).
6. Open `?edit` again, type ` zz`, and reload. The browser's own leave-page prompt appears. Cancel keeps the buffer.
7. `Mod-s` to save, then click a sidebar link. No dialog appears, because the buffer is clean. Revert with `git checkout pages/weekly-review.md`.
8. In `?edit`, change line 2 to `title: Weekly review: x` and press `Mod-s`. The preview alert reads `pages/weekly-review.md:2:8`, and the message no longer says `at line 1`.
9. Stop the dev server, add the same broken line, and run `bin/biac build`. The error names `pages/weekly-review.md:2:8`. Revert.

Before (measured 2026-10-11, baseline pass): see the table in [Gap analysis](#gap-analysis--what-we-already-have-vs-the-references).

## Who else implements this

Two features, counted separately.

**Unsaved-changes guard (GAP-007)**

| Repo      | Has it | Entry points                                                                            | Approach in one line                                                                                                   |
| --------- | ------ | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| evidence  | ABSENT | no `beforeunload`/`beforeNavigate` hit outside tests                                    | Pages are edited in the author's own editor; no in-app buffer to lose                                                  |
| framework | ABSENT | `research_repos/framework/src/client/sidebar-init.ts` (only `beforeunload` in the repo) | Its `beforeunload` saves the sidebar's `scrollTop` to `sessionStorage`; it guards nothing, and it has no in-app editor |
| mosaic    | ABSENT | no hit                                                                                  | Library, no authoring surface                                                                                          |
| streamlit | ABSENT | no `beforeunload`/`unsaved` hit under `frontend/`                                       | Apps are authored in the user's editor                                                                                 |

**Count:** 0 of 4. That is expected: none of them ships an in-browser source editor, and ours does ([ADR-0010](../adr/0010-page-authoring-is-dev-server-only.md)). An in-browser buffer that can be lost needs a guard. The bar is the platform's own unsaved-data pattern: MDN `Window: beforeunload event` (https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event). The router's own blocker API is already installed, so this is a justified invention, not a new dependency.

**Front-matter error position (GAP-008)**

| Repo      | Has it  | Entry points                                                                                                                                            | Approach in one line                                                                                                                                          |
| --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| evidence  | PARTIAL | `research_repos/evidence/core/src/utils/parseFrontmatter.ts`, `research_repos/evidence/core/src/user-components/custom-components/build-custom-tags.ts` | js-yaml `YAMLException.mark.line` → markdoc `lines`/`location.start.line` as `mark.line + 1` (file-relative); the column is dropped                           |
| framework | PARTIAL | `research_repos/framework/src/frontMatter.ts` (`readFrontMatter`)                                                                                       | gray-matter; on a YAML error (`"mark" in error`) it prints `console.warn("Invalid front matter:", error.reason)` and renders the page with `{}` — no position |
| mosaic    | ABSENT  | —                                                                                                                                                       | No markdown pages                                                                                                                                             |
| streamlit | ABSENT  | `research_repos/streamlit/lib/streamlit/elements/mermaid_chart.py` is the only `yaml`/front-matter hit: Mermaid diagram front-matter, not pages         | No markdown pages                                                                                                                                             |

**Count:** 2 of 4 parse page front-matter, and neither reports a file line and column. Our own page-body errors already do (`src/engine/page-compile-error.ts`, `src/engine/compile-page.ts` blank-line padding). That is the bar the same error surface already meets.

## Trade-offs and what we adopt

| Axis                               | Options seen (repo → approach)                                                                                                                                       | Trade-off                                                                                                                                                                                   | Our choice, and why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirm UI for in-app navigation   | `useBlocker` + `window.confirm`; `useBlocker({ withResolver: true })` + an in-app alert dialog                                                                       | Native: no new primitive, matches the reload prompt, but headless tests must handle a `dialog` event. In-app: styleable and DOM-testable, but adds a Base UI `AlertDialog` wrap and stories | **Native `window.confirm`** (decided 2026-10-11 by the project owner). `confirm` is injected into the hook as a parameter, so unit tests pass a named fake                                                                                                                                                                                                                                                                                                                                                    |
| What counts as unsaved             | `EditorStatus` kinds in `src/web/src/features/editor/types.ts`                                                                                                       | `saving` may still fail; `saveFailed` means the buffer never reached disk                                                                                                                   | **`dirty`, `saving`, `saveFailed`** are unsaved; `loading`, `loadFailed`, `clean`, `saved` are not. One pure `hasUnsavedChanges(status)` in `src/web/src/features/editor/editor-status.ts`                                                                                                                                                                                                                                                                                                                    |
| When to block                      | `shouldBlockFn({ current, next })`                                                                                                                                   | Blocking every navigation would prompt on harmless in-editor URL changes                                                                                                                    | **Only when `next` leaves the editor**: a different `pathname`, or `next.search` no longer an edit search (`isEditSearch` in `src/web/src/features/editor/edit-search.ts`). Filter writes use `history.replaceState` (`src/web/src/features/filters/filter-url-port.ts`), so they never reach the router                                                                                                                                                                                                      |
| Reload / tab close                 | MDN `beforeunload` (`preventDefault()` + legacy `returnValue`); router's `enableBeforeUnload`                                                                        | Hand-rolled listener duplicates what the router installs                                                                                                                                    | **`enableBeforeUnload: () => hasUnsavedChanges(status)`**. The prompt text is the browser's; MDN notes it only shows after a user gesture on the page (sticky activation), and typing in the editor is one. MDN advises listening only while changes are unsaved; `@tanstack/history` 1.162.4 (`dist/esm/index.js`, `createBrowserHistory`) already keeps one capture-phase `beforeunload` listener for the app's lifetime and asks each blocker's predicate, so a hand-rolled listener would be a second one |
| Where the YAML position comes from | evidence → `YAMLException.mark.line + 1`; framework → none; ours → `yaml` 2.9.1 `YAMLParseError.linePos[0] = { line, col }` (1-based, counted within the YAML block) | Importing `yaml` to `instanceof` it adds a direct dependency on what is vfile-matter's transitive dep                                                                                       | **Duck-type `linePos`** on the thrown error, as `errorPosition` in `src/engine/page-compile-error.ts` already duck-types `line`/`column`. vfile-matter 5.0.1's regex `^---(?:\r?\n\|\r)` puts exactly one line before the YAML, so **file line = `linePos[0].line + 1`**, column unchanged                                                                                                                                                                                                                    |
| The message                        | yaml's `prettifyError` appends ` at line N, column M:\n\n<snippet>\n<caret>` (`yaml/dist/errors.js`)                                                                 | Leaving it in shows a block-relative line next to the file-true `file:line:column`                                                                                                          | **Strip ` at line N, column M`, keep the snippet and the caret**: the snippet is the offending source line, and the caret's column is the same in the file                                                                                                                                                                                                                                                                                                                                                    |
| One fix for both paths             | `compilePage` (dev preview) and `readPageFrontmatter` (discovery, `biac build`) both call `matter`                                                                   | Fixing one path leaves `biac build` reporting block-relative positions                                                                                                                      | **One helper in `src/engine/page-frontmatter.ts`** used by both, so the error carries `line`/`column` and `pageCompileError` picks them up unchanged                                                                                                                                                                                                                                                                                                                                                          |

## Deviations

- No in-app dialog primitive: in-app navigation uses `window.confirm`. A later slice may swap the injected `confirm` for an in-app dialog without touching the guard's logic.
- Front-matter errors keep failing loudly (the compile-error alert), unlike framework's warn-and-render.

## Open decisions

None. Whether the "block only when leaving the editor, ask natively" rule becomes ADR-0012 is settled in T3: if T2's code comment carries it fully, there is no ADR.
