# SL-017 — Edit a page in the browser and watch it re-render as I save

Milestone: Phase 1 · State: open · Depends on: SL-016 · Closes: —

> Delete this file when the slice ships. No `GAP-NNN` exists for this capability yet — R3 (the usability audit) is queued after this slice.

## Outcome

In `biac dev`, a report author opens any page in a split-pane editor (CodeMirror source on the left, the live rendered page on the right), saves with `Mod-s`, and the file in `pages/` changes and the preview re-renders without a full reload — today the only way to change a page is an external editor, and every save full-reloads the SPA.

## Demo

1. Cold start: `pnpm build && bin/biac dev`, open `http://localhost:5175/weekly-review`.
2. The header shows an `Edit` link (dev only). Click it — the URL becomes the edit route for `pages/weekly-review.md`; the left pane holds the page source, the right pane the rendered page.
3. Change the first heading's text and append `limit 5` to the ` ```sql order_detail ` fence (no fence on this page has a `LIMIT` to change); the status shows `Unsaved changes`. Press `Mod-s`.
4. The status shows `Saved`; `git diff pages/weekly-review.md` shows exactly that edit; the right pane shows the new heading and both `order_detail` tables at 5 rows, and the editor kept its buffer, cursor position and scroll (`window` marker survives — no full reload).
5. Pick `Region = West` in the preview, then save another edit — `?region=West` stays in the URL and the dropdown keeps its value.
6. Type a broken MDX tag (`<Callout`) and save — the right pane shows the page error, the editor stays usable; fix it, save, the page renders again.
7. Reload the browser — the edit is still there (it is on disk).
8. `bin/biac build && bin/biac preview` → `/weekly-review` has no `Edit` link, and `grep -rl codemirror build/` prints nothing.
9. Restore: `git checkout pages/weekly-review.md`.

**Count:** live preview 3 of 4 (we already have a crude form of it); an in-browser page-source editor 0 of 4 in-repo (evidence ships one as a separate product — the strongest precedent that BI-as-code users want it); a save endpoint 0 of 4. The editor and the save endpoint are **inventions**. Justification: the backlog commits to an in-browser authoring loop; a browser editor cannot persist to `pages/` without a write path, and the dev server is the only process that can own one. The invention is bounded to `biac dev` — nothing ships in a static build.

## Deviations

- No reference writes page source from the browser; the save endpoint is an invention bounded to `biac dev`. Its security rules are stated in a comment at the middleware and, if they outlive the slice, in an ADR.
- We re-render the whole page on a content edit instead of framework's per-cell patch — we have no cell model; the query registry's SQL keying is what keeps unchanged queries from re-running.

## Out of scope

- Creating, renaming or deleting pages from the browser — a later authoring slice.
- Editing `biac.config.ts` or `data/` files.
- SQL autocomplete / schema-aware completion — Platform phase ("query console").
- Concurrent-edit conflict detection (disk changed under an open buffer beyond a reload prompt) — later, if the audit measures it.
- Any editor or write path in a static build — permanently, by design.
