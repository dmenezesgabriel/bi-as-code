# SL-014 — Chart-driven selections: click, brush and legend publish clauses

Milestone: Phase 1 · State: open · Depends on: SL-013 · Evidence: `docs/research/interaction-reference.md` (R2) · Closes: —

> Written per `docs/slices/_TEMPLATE.md`. Every `research_repos/` path below was verified with `test -e` in the session that wrote this file (2026-10-09). Line ranges rot — paths are the citation; open the file.

## Outcome

A user clicks a chart mark, drags an interval brush over a continuous axis, or toggles a legend entry on a chart that declares `select="crossfilter"`, and every widget consuming that selection re-queries — while the publishing chart keeps its own rows (cross exclude-self) and dims its unselected marks.

## Demo

1. Cold start: `bin/biac dev`, open `http://localhost:5175/weekly-review`.
2. Record before numbers: `<BarChart>` bar count, `<Histogram>` bin count, `<Table data="region_week">` and `<Table data="order_detail">` row counts, Region `<Dropdown>` option count, `console` output.
3. Click the `West` bar of `<BarChart data="orders" x="region" y="revenue" select="crossfilter">` — the scatter chart, histogram and both tables narrow to `region = 'West'`; the bar chart itself keeps all bars (its clause skips its own client) and dims the non-West bars; the Region dropdown's option list narrows to `West` (its options query is not the clause's publisher).
4. Click `West` again — the clause clears; every widget returns to unfiltered counts.
5. Drag an interval brush across `<Histogram data="order_amounts" value="amount" select="crossfilter">` — `order_detail` narrows to the brushed amount window, the histogram keeps its full shape, and the Amount `<Slider>` bounds contract (its bounds query consumes `amount`, not its own clause).
6. Toggle a series off in the `<ScatterChart>` legend (`series="region"`) — `region_week` widgets narrow to the enabled regions; the legend's native hide/show still applies.
7. Reload — chart selections are session-state: no URL params appear for them, nothing persists (decision 2 below); `?region=…` params authored through inputs behave exactly as before.

**Named disagreements the slice must resolve** (evidence sides differ, so these are ours to pick):

- mosaic interacts against an author-named selection (`as: $sel`); our markdown has no params block — the publish target must come from the widget's own bindings (decision 1).
- mosaic's `Highlight` issues a per-mark test query to find unselected marks; our chart already holds its rows client-side (decision 6).
- mosaic brushes over its own scale wrappers (`invert.js` delegates to `scale.invert`); ours must convert ECharts brush output — `brushSelected` areas carry `coordRange` in data space, no pixel math needed (decision 4).

## Deviations

- De-emphasis is computed locally from the published clause value, not by a per-mark test query (`Highlight.js` `predicateFunction` issues one query per mark per update — our publisher knows what it selected).
- `peers` is not ported: one widget = one EChart = one client; `clients = {own client}` is the whole semantic.
- Mosaic's `as:` (author-named selection channel) is not ported: the target selection is the bound field's name — our filter id ⇄ column convention. An author-named channel is additive later if needed.
- `activate()` (pointerenter → prefetch hint) is not ported — it exists to feed preaggregation, SL-015 scope.
- `Nearest`, `Region`, `Interval2D`, `PanZoom` are not ported this slice; `Region`'s rect→values semantic is covered by category-axis brush → `clauseList`.
- Shift/meta accumulation emits `clauseList` (multi-value `IN`), not mosaic's `clausePoints` N-field tuple clause — our clicks bind one field.

## Open decisions

None — decisions 1–8 in Trade-offs are settled with evidence above. The one residual the executor must not "fix": clauses from a chart and an input on the same named selection AND together (mosaic's intersect semantics — replace-by-source is per publisher, not per field).

## Out of scope

- `nearest`, `region`, `intervalXY`, `panZoom` interactors; mosaic's `activate` prefetch (SL-015 with debounce/consolidation/preagg).
- Author-named selection channels (`as:`) and `select` values other than `"crossfilter"`; selection reflection back into input displays or the URL (decision 2 records why).
- `empty: true` authoring; multi-field `clausePoints`/`clauseIntervals` (not needed — our interactors emit single-field clauses).
- `include` relays for chart selections (the `Selection` flag shipped in SL-013; no chart consumer demands it).
