# SL-004 — `<Table>` widget: sort, pagination, loading/error/empty

Milestone: Phase 1 — A usable BI-as-code product · State: open · Depends on: SL-003 · Closes: —

## Outcome

A page author writes `<Table data="weekly_trend" />` in a `.md` page and the named query's result renders as a sortable, paginated table — header clicks cycle sort direction, a pager appears when the result exceeds `pageSize` — while the named ` ```sql ` fence's inline result renders through the same component.

## Demo

1. Cold start: `pnpm install && pnpm build:cli`, then `bin/biac dev` from the repo root, open `http://localhost:5175/weekly-review`.
2. The `<Table data="weekly_trend" />` under the `weekly_trend` fence renders 10 rows and a pager (`39 rows`); `Next` shows rows 11–20, `Last` page 4 (rows 31–39).
3. Click the `orders` column header: rows sort descending; click again: ascending; a third click restores the authored `order by week, region`. Assert `aria-sort` tracks each state.
4. The ` ```sql weekly_trend ` fence's own inline result now renders the same component (sortable headers present there too).
5. Open `http://localhost:5175/?region=Atlantis` — the `<Table data="orders" />` on the index page shows its empty state (the registry re-ran with the bound param; the result is legitimately 0 rows).
6. Temporarily repoint one `<Table>`'s `data` at a name no ` ```sql ` block declares — the table shows an inline error naming the unknown query; the rest of the page renders. Revert.
7. Sort/page never re-run the query: interactions are instant, `console` stays clean.

## Deviations

- **Client-side sort/page** — evidence and mosaic push into SQL; framework and streamlit don't. Deferred deliberately: SQL pushdown becomes interesting with `data=<raw table>` and cross-filter clauses, both of which SL-013/SL-014 own; a comment at the sort site names this.
- **No row selection / `as`/`filterBy`** — mosaic's Table and Inputs.table both emit selections; SL-014 owns that axis.
- **No `search` box** — evidence's is SQL-pushdown search; the inputs slices (SL-010–SL-012) own filtering UX.
- **No column formatting/reorder/`columns` subset/`format` callbacks** — "Table extras" later-phase row (download, column filters, column config, pivot).
- **No download/fullscreen/subtotals/pivot** — same later-phase row.
- **`data` resolves only named ` ```sql ` blocks** — evidence also accepts `source.table`; our fallback would be `select *` against a registered table, a second data path v1 deliberately lacks.
- **`st.table`-style static variant absent** — every `<Table>` is interactive; static rendering stays with gfm `| |` tables.

## Open decisions

- **Pager composition** — settle in T2 by reading `TablePagination.svelte`: adopt first/prev/next/last + "Page i of n · N rows" verbatim unless our chrome argues otherwise.
- **Reset behavior on data change** — when `{{params}}` re-run changes `rows`, page clamps to the new range (a now-empty page must not render nothing); settle in T2 with a unit test.
