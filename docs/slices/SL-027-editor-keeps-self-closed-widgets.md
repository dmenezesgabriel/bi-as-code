# SL-027 — The source editor leaves a self-closed widget as typed

Milestone: Phase 1 — Known debt · State: partial · Depends on: — · Closes: the Known-debt "source editor appends a closing tag to a self-closed widget" row in `docs/backlog.md` (no `GAP-NNN`; the row postdates the usability audit)

## Outcome

An author who types `<Table data="orders" />` or `<Details />` in the source editor gets exactly that, and the page compiles on save, instead of the editor appending `</Table>` / `</Details>` and the save failing with "Unexpected closing slash".

## Demo

A numbered script a human runs from a cold start. Steps 2–6 edit `pages/index.md` through the editor; step 7 restores it.

1. Cold start: `pnpm build:cli && bin/biac dev`, open `http://localhost:<port>/?edit=true`.
2. On a new line at the end of the source, type `<Table data="orders" />` key by key. The line reads exactly that — no `</Table>` after the cursor.
3. Save (`Mod-s`): the preview renders the table; no compile-error page.
4. On a new line type `<Details />`: left as typed; save — the preview compiles.
5. On a new line type `<Details title="More">`: the editor still inserts `</Details>` after the cursor (a widget with children keeps its auto-close). Type `Body` between the tags, save — the preview shows the disclosure.
6. On a new line type `<BarChart data="orders" x="region" y="revenue" />` and `<TextInput id="q" />`: both left as typed, as before this slice.
7. Remove the added lines, save, `Done`; `git diff -- pages/` is empty.
8. `bin/biac build` passes and ships no `codemirror` (ADR-0010).
9. Console stays clean on every step.

### Specs

| Concern                              | Source                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Why only some tag names fail         | https://spec.commonmark.org/0.31.2/#html-blocks — type 6 starts when a line begins with `<` + one of a fixed, case-insensitive list of block tag names (`details`, `table`, `div`, …) followed by a space, `>` or `/>`. So `<Table ` is already HTML while it is being typed, and the auto-close's `isActiveAt` check passes. Type 7 (any other tag, e.g. `<BarChart`) needs a complete open tag, so before the closing `>` is typed the line is paragraph text and the handler stands down |
| Why `/>` is the page's normal syntax | https://mdxjs.com/docs/what-is-mdx/ — "HTML syntax doesn't work in MDX as it's replaced by JSX (`<img>` to `<img />`)": pages are MDX, where `/>` closes any component, while lang-html's default dialect is plain HTML, where `/>` closes nothing                                                                                                                                                                                                                                          |

**Where the sources disagree:** lang-html defaults to HTML semantics (`/>` is not a self-close), and our pages are MDX (JSX semantics, `/>` always self-closes). That disagreement is the defect, and the slice settles it in favour of the page language.

## Trade-offs and what we adopt

| Axis                                       | Options seen (source → approach)                      | Trade-off                                                                                                                                                                                           | Our choice, and why                                                                                                                                                                                           |
| ------------------------------------------ | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| How to stop the stray close tag            | lang-html → `html({ selfClosingTags: true })` dialect | Parses `/>` the way MDX does; the auto-close keeps working for tags with children (measured below)                                                                                                  | **Adopt**                                                                                                                                                                                                     |
|                                            | lang-html → `html({ autoCloseTags: false })`          | Removes the bug and the auto-close for `<Details title="x">` too — a regression for widgets with children                                                                                           | Reject                                                                                                                                                                                                        |
|                                            | lang-markdown → `completeHTMLTags: false`             | Turns off the `<` completion list only; the auto-close lives in lang-html, so the bug stays                                                                                                         | Reject — does not fix it                                                                                                                                                                                      |
| Keep `matchClosingTags: false`             | lang-markdown's own default                           | Passing our own `htmlTagLanguage` replaces the default wholesale, so its `matchClosingTags: false` must be restated or mismatched-close highlighting turns on across markdown-separated HTML blocks | Restate it: `html({ matchClosingTags: false, selfClosingTags: true })`                                                                                                                                        |
| Depend on `@codemirror/lang-html` directly | today it resolves only through lang-markdown          | Importing a transitive package breaks under pnpm's strict layout; a direct dep must be pinned (`save-exact`) and pass `minimumReleaseAge`/`trustPolicy`                                             | Add `@codemirror/lang-html` `6.4.12` — the version the lockfile already resolves, so no new code enters the tree; it stays behind `features/editor/` (`.dependency-cruiser.cjs` already covers `@codemirror`) |
