# SQL tables and fences

A page queries data with SQL, and DuckDB runs the query in the reader's browser. The `sql:` key registers a data file as a table, and a ` ```sql ` fence with a name runs a query over the registered tables and hands its result to the widgets on the page. This page shows how the fence appears; the table registration has no component, so it is text only.

The reader-facing reference is `docs/pages/sql/sql-tables-and-fences.md` (`/sql/sql-tables-and-fences` in `bin/biac dev docs`); each way a fence shows has a story here.

## Registering tables

`sql:` maps a table name to a file under `data/`. It goes in a page's front-matter, or in `biac.config.ts` to give every page the table. The value starts with `data/` and ends in `.csv`, `.json`, `.arrow` or `.parquet`. A page and `biac.config.ts` that declare the same name are an error, not an override.

```yaml
sql:
  penguin_rows: data/penguins.csv
```

## Named fences

A fence whose info string starts with a name is a query, and the name is how widgets find its result: `data="name"`. The stories below stand a fake DuckDB behind the fence, so they show the fence and never a real query.

## Echo and display

A named fence shows nothing by default. `echo` shows its SQL, highlighted, and `display` shows its result as a table that sorts by column, with headers in title case: `avg_body_mass_g` reads Avg Body Mass G. A bare flag or `=true` turns one on, and `=false` or leaving it out turns it off.

## Fence attributes

A flag the fence does not know, a name that is a flag, a name with `=` in it and a name that starts with `/` are errors that name the file and line, and they stop the build and the dev server before a page renders. The reader-facing page quotes each message.
