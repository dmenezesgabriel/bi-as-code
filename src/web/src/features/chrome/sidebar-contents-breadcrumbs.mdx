# Sidebar, table of contents and breadcrumbs

Three pieces of chrome help a reader find their way: the sidebar lists the site's pages, the contents rail lists the headings of the page on screen, and the breadcrumbs show where that page sits.

The reader-facing reference is `docs/pages/pages/sidebar-contents-breadcrumbs.md` (`/pages/sidebar-contents-breadcrumbs` in `bin/biac dev docs`). It describes how each piece is built and what a reader can do with it; the front-matter and config keys that switch them are on the Markdown pages and `biac.config.ts` pages.

## The sidebar

The sidebar is built from the files under `pages/`: the site name, the search box, the pages directly under `pages/` as links, then one collapsible group for each folder directly under `pages/`.

```text
pages/
  index.md              Home, always first
  getting-started.md    a link at the top level
  sales/
    weekly.md           a link inside the Sales group
    monthly.md
```

## Showing and hiding the sidebar

The ☰ button, named Toggle sidebar, shows and hides the sidebar and reports its state in `aria-expanded`.

The `App/SidebarToggles` story clicks the button and checks `aria-expanded` and the sidebar leaving the page. A docs canvas is narrower than 1024 px, where the sidebar is a drawer that starts closed, so that story runs under `App` in the sidebar and not here.

`nav.sidebar: false` in `biac.config.ts` removes the sidebar and its button from every page.

```ts
export default { nav: { sidebar: false } };
```

<Canvas of={AppStories.NoSidebar} story={{ inline: false, height: "420px" }} />

A page that keeps the sidebar but sets `header: false` keeps the toggle as a small floating button.

```yaml
header: false
```

The `App/PageWithoutHeader` story shows it, and runs under `App` in the sidebar for the same reason.

### Anchors

A heading that sets its own `id` keeps it. Any other heading gets one made from its text, and a repeat takes the next free number.

```md
## Revenue

```
